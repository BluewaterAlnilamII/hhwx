# 卡牌搜索

[English](bandori-card-search.md)

适用范围：卡牌图鉴、账号头像选择器、档案卡库及添加卡牌弹窗，以及组队计算器的已拥有卡牌排除区和临时添加卡牌弹窗。各入口共用搜索规则和筛选控件；按 Enter 或搜索按钮后才提交，保留输入法组词保护。

各场景先确定候选范围：头像选择器展开冲突实体，档案添加限定档案服务器，临时添加保留 JP 回退，已拥有卡牌搜索仅检查传入卡库；搜索再缩小这个范围。例如国服档案输入 `en`，只匹配已拥有且同一实体也在 EN 可用的卡牌，不能选到同数字 ID 的另一张 EN 实体。

## 匹配约定

- 使用 NFKC、忽略大小写并统一空白，保留标点。先识别明确列出的多词完整乐队名，再按空白分词。
- 同一个词的结构含义取并集，不同词取交集。未识别词在同一实体的 JP/EN/TW/CN 卡名、角色名、技能名和技能说明中进行忽略大小写的子串搜索。
- 已识别条件没有结果时，不回退文字搜索。`happy` 表示属性，`lock` 表示六花，即使卡牌文字中也包含这些词。
- `/special` 或 `"special"` 强制仅匹配各语言卡牌名称，不搜索角色名或技能文字，也不解释关键词、ID 或数值条件。斜杠作用于紧随其后的一个词；含空格的名称用 `"Hello, Happy World!"`。英文双引号和中文双引号 `“…”` 均可用，不要求整个名称相等。短语必须在同一个名称字段内连续出现；其余词与可见筛选仍取交集。空名称条件不匹配任何结果；未闭合引号将余下输入作为名称短语。
- 搜索与现有筛选按钮取交集。服务器词检查实体的可用服务器，不改变首选服务器、展示语言或排序。
- CN/EN 冲突实体保持独立，包括名称和技能匹配；不按数字 ID 合并。资料缺失不影响卡牌参与无关条件的查询。
- 点击输入框内的清除按钮或删空文字会立即移除搜索条件，保留其他筛选和排序。非空输入仍需提交，输入法组词过程不会清除搜索。原有清空全部按钮仍会重置所有筛选。
- 排序只改变顺序；缺失发行日期的卡牌在正序、倒序中均放在末尾。

## 语法

| 输入 | 含义 |
| --- | --- |
| `4` | ID 4 或四星或搜索技能倍率为 4% |
| `115` | ID 115 或搜索技能倍率为 115% |
| `#115` | 精确 ID 115 |
| `115%` | 仅查搜索技能倍率 115% |
| `4*` | 恰好四星 |
| `4*+`、`4*-` | 仅比较星级：至少／至多四星 |
| `>=4*`、`<=4*` | 分别等价于 `4*+`、`4*-` |
| `>4*`、`<4*` | 仅比较星级，不含边界 |
| `115+`、`115%+`、`>=115`、`>=115%` | 搜索技能倍率 ≥115% |
| `115-`、`115%-`、`<=115`、`<=115%` | 搜索技能倍率 ≤115% |
| `>115`、`>115%` | 搜索技能倍率 >115% |
| `<115`、`<115%` | 搜索技能倍率 <115% |
| `>4` | 星级 >4 或搜索技能倍率 >4% |
| `4+`、`4-` | 分别为“星级 ≥4 或倍率 ≥4%”、“星级 ≤4 或倍率 ≤4%” |
| `>=4`、`<=4` | 分别等价于 `4+`、`4-`，保留并集含义 |
| `r cool 4*+` | Roselia、Cool、至少四星同时成立 |
| `hikawa` | 日菜或纱夜 |
| `jp en` | 同一个实体同时在 JP 和 EN 可用 |
| `135% 分卡` | 搜索技能倍率为 135% 的分卡 |

裸数字接受正的安全整数，允许前导零；只有 1–5 具有星级含义。显式百分号接受完整的非负十进制数。`#10001abc`、`6*` 等错误的显式数字格式不匹配任何卡牌，不截取有效前缀、不忽略条件。

比较使用与精确倍率查询相同的搜索倍率。不带单位时，合法的星级与倍率条件取并集；`*` 限定星级，`%` 限定倍率。比较符不应用于卡牌 ID。`115%+ <150% 分卡` 要求分卡倍率至少 115%、低于 150%；缺失技能倍率不会满足上界条件。原来裸写的 `4+` 等星级范围查询现在也包含倍率含义；仅查星级请使用 `4*+`。

图鉴中的 `?q=` 保存提交的查询。原有 `?id=4` 链接仍精确查 ID，相当于 `#4`。既有筛选和排序 URL 参数的含义保持不变；其他选择器继续使用本地筛选状态。

共用的搜索按钮旁 `?` 移入时立即显示十类条件示例（包含名称搜索），移出按钮时立即收起；点击后保持展开，再次点击、点击外部或按 Escape 关闭。触屏与键盘也可操作同一按钮。打开帮助不会提交搜索；在选卡弹窗内按 Escape 会先关闭已展开的帮助。

共用控件依次排列搜索、服务器、乐队、属性、稀有度、角色、卡牌类型和排序；各场景适用的服务器和综合力排序继续保留。内容表面使用面板角色，帮助浮层使用浮层角色，浅深两种模式均遵循当前[主题指南](theme-guide.zh-CN.md)。紧凑缩略图网格、虚拟滚动、卡面切换和确认操作保持原行为。

共用工具栏使用放大镜提交按钮、“清空”和即时展开的 `?` 帮助。筛选选中态使用弱选中的背景、文字和圆环角色，实色选中控件使用强选中配对。结果数量使用面板底色、信息文字和边框，数字采用等宽数字并预留至少四位字符宽度。这些样式由主题角色和共享组件维护。

全站首选服务器属于带版本的浏览器偏好；图鉴查询与排序属于 URL 状态，选择器筛选属于局部状态，均不写入全站偏好。卡牌查询修改同步合并到当前浏览器 URL，保留之前的操作、语言路径和锚点，不触发服务器导航；返回列表快照仍仅存于当前会话。服务器候选范围变化时，原本全选的一组跟随新范围全选，明确清空的一组继续为空，部分选择仅保留仍可用的选项；其他条件保持不变。可选的浏览器持久化失败不得阻断当前界面操作。

## 关键词与技能

已确认的三音节名字缩写：`ksm`→香澄、`ars`→有咲、`hmr`→绯玛丽、`tme`→巴、`tgm`→鸫、`kkr`→心、`kor`→薰、`hgm`→育美、`msk`→美咲、`cst`→千圣、`ykn`→友希那、`msr`→真白、`nnm`→七深、`tks`→筑紫、`tmr`→灯。本次核对范围不含 RAS，拨音 `ん` 和长音不另计音节；这些缩写逐项登记，不自动推导，`msr` 只对应真白。

- [复审后的角色和乐队别名](../src/lib/bandori/cards/search-aliases.ts)明确列出 `r`、`m`、`go`、`chu2`、`chuchu`、`chu`、美咲／米歇尔两种身份、姓氏及确认的拼写变体。不使用前缀匹配、昵称推导、去标点或 CP 缩写扩展。
- [解析器](../src/lib/bandori/cards/search.ts)列出属性、可用服务器及卡牌类型别名，检查与对应筛选按钮相同的元数据。
- `score`、`scorer`、`分`、`分卡`：含加分效果，且不含回复或判定强化。
- `plock`、`判`、`判卡`：判定强化；`lock` 专用于六花。
- `heal`、`healer`、`奶`、`奶卡`：生命回复。复合技能可以同时满足回复与判定条件。
- 固定及条件档位取最高定义档位，包括同团／同属性条件，不计算当前队伍是否满足。逐音符累积成长型使用初始倍率：100% 成长至 150% 的技能匹配 100%，不匹配 150%。
- 倍率与技能类别独立。`100% heal` 可以匹配回复技能，`100% scorer` 会排除回复技能；持续时间、回复量和缺失地区值不参与倍率比较。
- 已拥有卡牌使用图鉴搜索口径，不随当前技能等级、特训状态或综合力改变；综合力仍可排序，不再成为隐式数字搜索字段，角色 ID 和乐队 ID 也不再拼入文字搜索。

本轮不实现未来发行后缀（`en+`）、否定、显式 OR、括号、特训状态或模糊拼写扩展。未知文字继续进行普通子串搜索。

## 实现与检查

目录与档案条目构建器按规范数据快照集中整理多语言及地区技能资料；每次筛选只解析一次查询，再检查各卡牌实体。展示投影、场景可用范围与规范搜索可用范围分开处理。既有未知资料策略继续生效；卡库允许显示的未知卡牌仍可使用精确 ID 匹配。

运行针对性的回归检查：

```sh
node --import tsx --test tests/bandori-card-search.test.mjs tests/bandori-card-catalog.test.mjs tests/bandori-profile-card-collection.test.mjs
```

搜索测试也已加入 `npm run test:bandori-cards`，覆盖全部确认别名、数字并集、多词交集、技能类别与倍率、多语言文本、缺失资料、实体冲突及筛选／排序组合。
