# 主题指南

英文主文档见 [theme-guide.md](theme-guide.md)。

本文是 Smile Patrol 浅色与深色网页 UI 的当前规范。CSS 是可执行的事实来源，本文说明配置归属与使用方式。[design-qa.md](../design-qa.md) 保存历史迭代和已被取代的方案，不作为另一份现行规范。

## 配置入口与归属

语言层 [layout](../src/app/[locale]/layout.tsx) 引入 `globals.css`，并通过 `data-visual-theme="smile-patrol"` 选择主题。`globals.css` 引入 Tailwind 和 `visual-theme/index.css`，后者先加载 recipes，再加载 Smile Patrol。浅深模式跟随浏览器的 `prefers-color-scheme`；目前没有独立的应用内主题开关或 JavaScript 配色表。

| 层次 | 修改位置 | 职责 |
| --- | --- | --- |
| 固定 palette 与 seed 映射 | [smile-patrol.css](../src/app/visual-theme/smile-patrol.css) | 九个 HHW 强调色、中性及功能输入、主题装饰效果 |
| 共用语义默认值 | [recipes.css](../src/app/visual-theme/recipes.css) | 跨主题的角色关系、操作按钮的成对颜色 |
| 当前主题与浅深模式值 | [smile-patrol.css](../src/app/visual-theme/smile-patrol.css) | 基础配置及浅深媒体查询覆盖；深色原生控件使用 `color-scheme: dark` |
| 共用外观 | [globals.css](../src/app/globals.css) | 消费角色的 `hhwx-*` 类；组件保留自身尺寸和布局 |

组件调用 `--theme-color-*`、`--theme-shadow-*` 和共享外观类，不直接调用 `--theme-seed-*` 或私有 `--smile-patrol-*` 输入。不要用组件内的站点颜色常量或 `dark:` 覆盖弥补角色缺失。只有现有角色无法表达实际职责时，才新增角色。

共用外观类位于 Tailwind 的 `components` 层，工具类可以覆盖它。因此，共享类接管外观后，要删除竞争的背景、文字、边框或阴影工具类。Tailwind 可能混淆颜色和宽度时，使用 `outline-[color:var(--theme-color-selection-subtle-ring)]` 等显式类型提示。

## 配色职责

九个 HHW 强调色 seed 保持固定。中性色及成功、警告、危险等功能输入单独配置，不属于新增的 HHW 品牌 seed。是否充分使用 seed 应按用途判断，不要求面积或出现频率相同。

| 固定 HHW seed | 浅色用途 | 深色用途 |
| --- | --- | --- |
| `#FFEE22` 亮黄 | 阳光背景色带混色 | 保留在 palette 中，不强行铺设亮黄底色 |
| `#FF9922` 橙 | 顶栏、主操作、斜线混色 | 小面积主操作 |
| `#44DDFF` 天蓝 | 占派生操作填充混色的 15% | 操作文字和图标、描边、选中页签、键盘焦点 |
| `#AA33CC` 紫 | 装饰槽 B | 提亮后的装饰槽 B |
| `#006699` 蓝 | 信息及操作文字与描边、操作填充混色的 85%、个人资料横幅、滚动条、装饰 C | 个人资料横幅；提亮的信息文字、装饰 C、背景银蓝混色 |
| `#F5A4CD` 粉 | 保留，不作普通文字色 | 页面标题 |
| `#F9E065` 柔黄 | 背景色带与导航 | 克制的当前导航强调 |
| `#EF392B` 红 | 页面标题、派生休息日文字 | 提亮后的休息日文字 |
| `#F35E38` 橘红 | 顶栏图标与装饰 A | 提亮后的顶栏图标与装饰 A |

浅色信息色使用 HHW 蓝 `#006699`，深色信息文字使用 HHW 蓝与白色各 50% 的混色。浅色操作文字和描边也使用 `#006699`，操作填充由 15% 天蓝和 85% HHW 蓝混合，约为 `#0A78A8`；信息与操作即使色值相同，也保留独立角色。深色操作文字和描边使用 `#44DDFF`，实色填充使用 `#0070A0` 并搭配反色文字。这是同一操作类别的两种表现，不是新增两个语义类别。状态文字可以独立提亮，不带动实色按钮底色。粉色承担标题强调而非错误提示。

## 组件用法与例外

| 用途 | 使用方式 |
| --- | --- |
| 页面面板 | `hhwx-panel`；嵌套内容调用面板背景并保留自身几何形状 |
| 中性按钮、输入框 | `hhwx-control`，适用时使用其选中和禁用态 |
| 蓝色实色操作 | `hhwx-action-accent`；自定义控件使用配套的 `action-accent-background` 与 `foreground` |
| 弱强调操作、链接、回复或展开按钮 | `action-secondary-*`；中性或浅着色表面，操作色文字与边框 |
| 实色成功、危险或错误重试操作 | 配套的 `action-success-*` 或 `action-danger-*` 背景和文字；未单独配置时悬停保留同一底色 |
| 弱强调破坏性操作 | 既有 `action-destructive-*` 角色；弱背景与实色危险反馈的职责分开 |
| 菜单、帮助、提示或对话框浮层 | `hhwx-floating-surface`；专用几何结构使用对应浮层角色 |
| 选中、焦点 | 各自的角色；即使颜色相同，也保持职责独立 |
| 活动完成度等只读进度 | `progress-*` 信息角色 |
| 可拖动播放进度与音量 | 填充或 accent 调用 `action-accent-background`，与播放按钮一致；自定义滑轨调用 `range-track-background` |

不要拿状态**文字色**、**边框色**或进度条颜色作为反色按钮文字的底色。状态圆点可以使用状态文字色，但有文字的实色按钮必须使用完整配对，例如：

```tsx
className="bg-[var(--theme-color-action-success-background)] text-[var(--theme-color-action-success-foreground)]"
```

常规焦点 ring、outline 和焦点边框使用 `--theme-color-focus-ring`，ring offset 跟随容器表面。保留的 `focus-ring-on-dark` 及 information-on-dark 配方服务于彩色顶栏；固定蓝色的资料横幅和媒体覆盖层可保留适合自身背景的反色焦点。这些表面例外不是应用浅深模式的选择入口。保留的 muted-on-dark 别名服务于图表文字。

排名按钮保留紧凑尺寸、圆环和间距，不添加勾选占位。原生下拉框保留中性背景，不继承选中容器的蓝色底色。组件几何形状不随浅深模式改变。

次要状态也遵循这些角色：操作悬停使用操作角色，选中项和页签使用选中及页签角色，信息提示和未读圆点保留信息角色。图片加载及不可用占位使用 `control-background-muted` 和 `text-muted`；它们属于 UI 反馈，不是领域图片。降低浮层内次要文字的透明度前，必须检查合成后的对比度。

两种模式都保留现有自定义滑块圆点的白色边缘。原生音量控件保留原生几何结构，accent 跟随操作实色填充。可拖动媒体进度不继承只读活动进度的颜色。

乐队颜色、卡面、图表数据系列、棋子和固定媒体覆盖层文字由业务内容管理。剩余局部 `dark:` 工具类用于图表系列红蓝文字，以及动态表情角标的边缘衬色，不是普通站点控件的用法范例。装饰性 Logo 改色时保留真实图标轮廓。

日历条保留乐队身份色、白色标签，不添加额外彩色描边。深色通过 `--theme-color-calendar-event-shade` 压暗原色条，浅色保持透明。浅色模式中，白字在部分明亮乐队底色上的低对比度仍是已接受的取舍，不能据此声称全站无障碍对比度全部通过。

PWA 安装颜色是单独的元数据，位于 `src/app/manifest.ts` 和 `src/app/[locale]/manifest.webmanifest/route.ts`。目前保留固定品牌黄色，不随 CSS 媒体查询变化。

## 加载与交互反馈

复用以下加载组件。区块加载沿用活动信息页的橙色转圈和下方次要文字，尺寸由所在页面、面板或对话框决定，不要求所有加载效果都占满屏幕。

面板首次加载统一等待必要依赖，不为每列或每个字段单独添加转圈。单张图片使用保留尺寸的占位；资源缺失或加载失败统一使用 `common.states.imageUnavailable`（“暂无图片”），不添加单图重试按钮或按图片类型细分文案。阻断页面或面板使用的数据加载错误仍保留重试操作。

| 组件 | 用途 |
| --- | --- |
| `LoadingIndicator` | 页面或面板的初次加载；`compact` 将小转圈和文字并排，用于行内区域 |
| `LoadingSpinner` | 操作按钮内的装饰性进度；保留可访问的按钮名称，需要继承按钮文字色时使用 `text-current` |
| `LoadingPlaceholder` | 数据等待期间预留图片或已知布局尺寸，提供本地化的可访问名称 |
| `LoadingImage` | 实际图片源加载完成前保持图片隐藏，复用占位并保留图片尺寸 |

初次显示应等待足以形成有效视图的必要数据。不能把零条结果、服务状态未知、默认卡牌身份或不完整的筛选项当成已经加载的内容。成功响应后才能显示空态；初次失败应结束加载，显示错误和失败依赖的重试入口，不同时显示误导性的空态。同一资源后台刷新时保留完整数据，刷新错误在旁提示；切换账号、条目或数据键时，不能继承上一个结果。

图片身份以解析后的实际 URL 为准。URL 改变时立即移除旧图，新图加载前显示占位；仅切换服务器但 URL 不变时，不重新挂载图片。元数据等待和随后的图片下载都需要反馈。需要保留图片引用以实现缩放、手势的查看器，可以继续使用按源 URL 设置 key 的原生图片，并覆盖居中的 `LoadingSpinner`。查看器不显示可见加载文字，状态容器为辅助技术保留通用的本地化加载名称。失败后结束忙碌状态。固定深色查看器覆盖层可以保留白色提示文字，普通图片占位仍使用上述主题角色。

悬停样式仅用于支持悬停的输入方式，手写 CSS 使用 `@media (hover: hover)`。指针预览由鼠标触发，键盘预览使用 `:focus-visible`。触屏第一次点击就执行操作，取消选中后不残留悬停选中外观；有明确用途的长按预览可以独立保留。Escape 先关闭当前预览，再处理其所属对话框；焦点原本在预览内时，关闭后回到触发按钮。按钮焦点样式使用 `focus-visible`，文本输入框可以保留编辑中的焦点提示。选择器筛选结果从有到无再恢复时，不能仅因结果区重新挂载就重置滚动容器。

共享加载提示和占位提供可访问的加载名称或状态，并使用 `motion-safe` 动画；请求减少动态效果时保留静态反馈。日历网格等专用布局骨架可以保留自身几何形状和主题颜色，但须遵守相同的状态和可访问性规则，不另创一套加载样式。

按受影响场景验证延迟响应、失败重试、成功空结果、缓存数据、图片 URL 改变与不变、浅深模式、减少动态效果，以及触屏和键盘操作。这些规则是相关组件的目标规范，不代表所有无关站点流程都已完成审计。

## 修改与验证方法

1. 修改前找到语义角色及全部消费者。调整面板时，在 Smile Patrol 对应媒体查询中修改面板角色；调整操作按钮时，一起检查背景、文字、悬停和禁用态。
2. 只有所有主题都适用的关系才写入共用 recipes；Smile Patrol 的具体值及浅深差异写入主题文件。两种模式保持相同组件结构。
3. 等颜色过渡结束后检查浅深两种模式的计算颜色，覆盖默认、选中、悬停、键盘焦点、禁用，以及适用的成功和错误状态，并检查紧凑移动端布局。既检查文字，也检查图标；仅扫描文字会漏掉图标按钮。
4. 检查未定义角色、无消费者别名和相互竞争的局部类。按 [CONTRIBUTING](../CONTRIBUTING.zh-CN.md) 选择既有测试、lint 和生产构建检查。打包可能影响级联顺序，因此要比较生产 CSS 的实际渲染；本地浏览器验证需要 CDN 数据时使用 `http://localhost:3000`。

普通文字至少达到 [4.5:1 对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，大字及有辨识作用的控件图形通常要求 [3:1](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。测量实际颜色配对及透明度合成结果，记录已接受的业务例外和未测状态，不以少数 palette 样本代替全站合规结论。
