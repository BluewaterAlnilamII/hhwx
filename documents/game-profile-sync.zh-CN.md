# 手动确认登录的国服档案导入

用户选择已绑定 UID，勾选同意并点击同步。浏览器在这次点击中预留空白弹窗，然后请求官方 Bilibili 登录链接。用户在官方页面完成登录，回到 HHWX 点击 **我已登录**。后端自动检查安卓和 iOS 角色，只导入与目标 UID 匹配的角色。

## 完整处理流程

正常情况下，浏览器向 `POST /api/account/game-profiles/sync` 发出两次请求：

| action | JSON 字段 | 成功结果 |
| --- | --- | --- |
| `start` | `action`、`gameUid` | `taskId`、`gameUid`、`status=waiting`、`loginUrl`、`expiresIn` |
| `confirm` | `action`、`gameUid`、`taskId` | 保存后的游戏档案摘要 |

响应沿用既有成功/错误结构并禁止缓存。拒绝未知字段、浏览器自报的任务归属、密码、Cookie 和 token。浏览器不会收到 Bilibili/游戏凭据或原始 suite。官方 TV 协议登录页可能显示其自身的 TV 品牌；密码和验证内容均在官方页面处理。

1. **创建：** HHWX 检查账号、邮箱和目标绑定一次，将已认证的用户 ID 和 UID 交给私有 user-fetcher。私有后端创建官方登录请求，每个用户只保留一条内存等待记录。重新同步会替换未执行的记录；正在执行的记录不能替换。
2. **等待：** 浏览器、HHWX 服务端、user-fetcher 和数据库均不进行状态轮询。等待记录自创建起五分钟过期，重试不会延长；官方登录码可能更早失效。浏览器只有一次到期定时器供界面恢复，后端独立清理，不依赖取消信号。关闭官方弹窗不会触发不可靠的跨域关窗检测。等待中的 UID 只显示“我已登录”和“取消同步”；取消仅清掉前端等待状态，不发 API、不领取 token，后端记录仍按原期限清理。取消后可重新同步，新请求替换未执行的旧记录。
3. **确认：** HHWX 验证请求的已签名登录身份，不重新查询账号、邮箱或绑定表。私有后端检查记录归属、UID、期限和重复执行，再尝试取得四个抓取名额之一。满额立即返回 `429 LOGIN_TASK_BUSY`，不联系 Bilibili、不排队；等待记录保留到原期限，可再次确认。
4. **抓取：** 获得名额后，后端只查询一次官方登录结果。尚未登录返回 `409 LOGIN_NOT_COMPLETED`，释放名额并保留等待记录。已登录则领取和交换 token，自动对照安卓/iOS 角色，再严格解码匹配角色的 suite 和自身资料。保留同一渠道账号互斥、RequestID 校验和响应大小限制；会话或版本状态不确定时停止，不猜测或重放游戏请求链。
5. **保存：** 私有抓取成功后才读取私有卡牌 master，沿用原来的规范化、gzip/SHA 存储及档案/称号 RPC。upsert 在取得原有事务锁后检查当前 UID 归属；解绑和绑定转移取得相同 UID 锁：保存先完成时，解绑删除已保存档案；解绑先完成时，后续保存拒绝旧账号。直接返回已保存行，不再补查摘要。必要的称号/效果合并失败会返回失败；之前已成功的档案写入不新增回滚机制，下次同步沿用原来的幂等 upsert。
6. **结束：** 前端使用返回摘要更新档案列表，不重新读取账号或档案列表。其余失败清掉等待状态并保留错误提示。私有操作退出时清理 token、渠道 key 和游戏会话头并关闭连接，不缓存抓取结果供保存重试。抓取名额一直保持到私有响应发送结束，通过 `finally` 释放；断网亦然。等待记录过期不能中止在途操作或提前释放名额。

私有抓取保留 120 秒操作期限及单次网络请求边界。内部转发允许 150 秒覆盖抓取和响应发送，浏览器确认请求允许 180 秒覆盖抓取及保存；发布时需核对反向代理支持这一有界请求。等待记录在现有 HTTP 服务循环中清理，不为每条记录开定时线程，也不引入数据库清理任务。

同意框默认关闭，只有框本身可以切换；手动确认按钮同样要求同意。等待期间不能重新同步或解绑该 UID，也不能为其他 UID 创建登录任务；确认请求进行中显示同步中并禁用确认和取消按钮。没有额外打开登录页或保存重试按钮。

## 配置、兼容和发布顺序

- 兼容后端和数据库迁移发布完成前，保持 `NEXT_PUBLIC_GAME_PROFILE_SYNC_ENABLED=false`。公开开关在构建时读取，同时控制页面和 API。
- 开启 Web 构建前应用 `20261001040725_snapshot_binding_lock_check.sql` 和 `20261001064438_lock_game_uid_unbind.sql`，分别修正 upsert 的锁与归属检查顺序、让解绑与保存/转移使用共同锁；保留仅供 service_role 使用的权限及现有表结构。
- 先发布私有后端，再发布匹配的 Web 构建。内部接口恢复为 `/internal/hhwx-user-fetcher/user-snapshot`，使用 `start/confirm`；过渡 `/snapshot-login` 和 `poll/result/cancel` 删除。旧 UID-only 内部请求仍不可用，不能回退到 bot 材料。旧 Web 请求缺少 action 时拒绝。
- 私有连接和后端凭据只供服务端使用，SDK 签名配置留在私有后端。不新增运行时依赖、队列、表或 RLS 策略。
- Web 关闭开关需要重新构建；不配置私有 SDK 材料也会禁用该能力。

2026-09-30 的实时安卓登录和 suite 验证属于历史协议证据，不能代替修改后 HTTP/界面的验证。当前离线和浏览器结果另行报告；模拟浏览器测试不能证明实时 Bilibili 或生产数据库行为。
