# 即时留言板

English version: [realtime-message-board.md](realtime-message-board.md).

本地实现默认关闭。生产迁移、账号授权和部署需要另行明确操作范围。见[执行计划](realtime-message-board-plan.zh-CN.md)和[验证记录](realtime-message-board-validation.zh-CN.md)。

消息和评论中的表情统一预留方形区域：行内为 24 CSS px，纯表情消息为 48 CSS px。图片在区域内等比显示，与选择面板采用相同的方形占位规则，但各自保留适合场景的尺寸。加载和失败状态维持相同尺寸，图片到达不会改变换行或阅读位置。复用现有加载组件，不维护逐图尺寸表或生成步骤；上传图片继续按已有元数据保留宽高比。

## 回复与回应（2026-10-27）

三个快捷回应默认依次为 `:Tae:`、`:KokoroYay:`、`:LisaMelt:`。从快捷行或完整面板主动选择表情并成功添加后，该表情移至最前，保留三个不重复的选择，不足部分按默认顺序补齐。点击已有回应标签追加、撤回回应、请求失败及其他用户的事件均不改变顺序。选择按账号保存在浏览器本地存储，同源标签页之间同步，不做跨设备同步。表情入口统一使用现成的 Lucide `SmilePlus` 图标。

消息支持引用一条原消息，并使用评论区现有的表情目录添加回应。右键、Shift+F10 和触摸长按打开消息菜单，不显示悬停操作工具栏。菜单首行提供三个快捷回应和完整表情选择器。已有回应的消息还会在回应标签旁显示评论区同款添加回应按钮。选择器复用评论区紧凑面板，不带标题或遮罩；表情网格保留原来的 256px 高度上限并在内部滚动，只调整弹出位置，不再额外缩短。消息菜单和留言板表情面板打开时锁住背景滚动。点击回应标签加入或撤回自己的回应；悬停、聚焦或长按预览参与者，消息菜单可打开分页参与者列表。禁言时可以查看参与者和撤回已有回应，不能添加回应。回应标签、表情网格和参与者弹窗复用评论区组件，不接入评论通知。

操作名称统一为“引用”（英文 Quote），菜单使用 Lucide 现成的 MessageSquareQuote 图标，预览保留原来的 CornerUpLeft 回转箭头。选择“引用”保留现有草稿，并在输入框上方显示可取消的预览（取消按钮或 Esc），不添加额外标题；改选另一条消息时替换目标。提交后清空引用状态。一批图片及随后文字中，**只有第一条待发送及已保存消息带引用**，后续内容以及之后普通发送的消息都不带引用，继续采用已有的作者/时间简并展示。主动选择的新引用总是重新显示作者分组。失败重试保持请求 ID 和引用目标；明确收到 `CHAT_REPLY_DELETED` 拒绝时提供“取消引用并重新发送”，不会自动改成普通消息。草稿和待发送媒体在失败及面板关闭后仍归当前账号会话保管。

引用仅显示直接原消息的当前作者名、最多 160 字摘要或图片标识，不递归展开引用。原消息删除后不再暴露正文；删除、到期清理或原消息缺失时统一显示 **“消息已删除”**，保留用于识别的原消息 ID。点击引用会定位并短暂高亮已加载的原消息；未加载时通过 `GET /api/chat/messages/[messageId]/context` 获取最多 50 条周边消息。临时上下文不会拼接不连续的历史，也不会把最新消息标为已读。沿用“跳到最新消息”返回主时间线，不提供“返回原位置”控件。两处视图均继续接收删除和回应更新。

`POST /api/chat/messages` 和 `/api/chat/images` 增加可选 `replyToId`；发送 RPC 增加有默认值的末尾 UUID 参数，旧调用保持有效。新回复的目标必须仍存在且属于同一房间，重试时目标也参与请求一致性检查。历史和发送结果增加可选 `reply`、`reactions`、`reactionsVersion`、`reactionsViewerId`。回应由 `PUT/GET /api/chat/messages/[messageId]/reactions` 调用仅服务端可执行的 `set_chat_reaction`、`read_chat_reaction_participants`，参与者按时间/UUID 分页。计数与本人选中状态分别按版本合并，处理 HTTP 和实时事件乱序。回应变化只向完整消息频道发布 `message.reactions`，不点亮摘要红点、不消耗发送配额、不产生个人通知。

已加载消息自身保存回应人数与本人选择的版本；只有尚未加载的消息 ID 需要暂存回应事件，合并时消费、删除时移除、会话结束时清理。超过 1,000 个回应 ID 不再重置时间线、裁剪历史或移动阅读位置。回应预览与完整名单按消息、表情和回应版本共享已完成/进行中的首页，后续页继续使用原游标接口。关闭预览不会取消名单仍在使用的请求；已打开名单保留选中表情、打开时的统计与已加载行，后续重新打开使用当前版本。共享评论组件行为保持不变。

引用/回应的初始阶段不含 @，后续单独确认的 @ 阶段见下节。引用仍无提醒开关，也不会自动通知被引用作者；不包含嵌套子线程。上线这些交互前先应用 `20261027093601_chat_replies_and_reactions.sql`；旧消息无须回填，旧客户端可忽略新增字段和回应事件。回滚应用时可保留新增列、表和带默认参数的 RPC。生产迁移和部署仍需单独操作。

## 在线成员与提及目录（2026-10-28）

在线人数放在左侧标题旁，点击打开带内部滚动的成员面板；面板只保留标题和成员行，不添加解释文案。消息头像及 @ 候选共用同一在线状态。统计保持站内摘要连接、符合资格的已登录账号，包括本人；同一账号多个标签页/设备只计一人。关闭留言板、标签页进入后台不会主动断开摘要连接。这代表站内连接状态，不代表正在阅读、拥有焦点或能够立即回复。访客不计入；异常断线由 broker 检测后移除，不持久化最后在线时间或写入数据库心跳。

只在 `chat_activity` 开启 `presence` 和 `force_push_join_leave`。全局加入/离开事件发送保持关闭，由签名连接的 `subs` 只为当前合资格且公开在线的账号开启，并附带其公开资料。`GET /api/chat/presence` 保留原有按账号去重的列表响应，新增 `?connections=1` 返回过滤后的 `{clientId,user}`，供首次订阅及每次重连建立基线；即使消息历史恢复成功，临时在线状态仍需重建。接口验证访问者，读取私有 broker API，再经仅服务端可执行的 `read_chat_online_users` 过滤当前资格和可见性；浏览器仍不能直接调用 broker presence/presence-stats。此后加入/离开事件直接更新连接表，不请求 HTTP；最后一个连接离开才移除该账号。基线读取期间发生的变化在显示前合并。开关任一弹窗、切换前后台都保留连接表，不重读；没有定时在线查询或全量校准。读取失败或断线显示未知，成员面板提供显式重试。消息/摘要继续使用既有推送和恢复方式。

Centrifugo 加入/离开事件至多投递一次，不属于可恢复的消息历史，因此重连时重建临时在线基线；连接仍健康时若静默丢失该事件，不使用定时器修补。当前设计范围是单 broker 部署。broker 心跳/ping 仍负责发现断线，但不获取成员列表，也不写数据库心跳。参见 [Centrifugo 在线语义](https://centrifugal.dev/docs/server/presence)和[签名订阅覆盖项](https://centrifugal.dev/docs/server/authentication#subs)。

私有 `chat_private.user_state.presence_visible` 默认为 true。经过认证的 `PATCH /api/chat/presence` 只接受当前账号的布尔 `visible`，实时校验 Auth，再调用仅服务端可执行的 RPC。随后以可重连状态码断开该账号已有 broker 连接；当前客户端在重连时取得新凭证。隐身凭证同时关闭 presence 登记和加入/离开事件，原有公开连接退出后，替换它的隐身连接不再出现。broker 操作失败返回错误，不声称已完成即时传播；已保存的偏好可重试应用。搜索和提及不受影响。**没有前端隐身开关**，也不增加离开/勿扰/手动状态或最后在线时间展示。

打开面板时，`GET /api/chat/users` 将完整轻量目录加载到账号所属的会话中，覆盖所有符合资格的账号，包括本人、离线和隐身用户。字段仅为已有公开账号/头像信息；目录和非空关键词搜索都不读取消息历史，不包含邮箱、可见性、连接元数据或私人活动。缓存可复用五分钟，过期后下次打开/从隐藏状态返回时更新，退出或切换账号销毁。搜索先过滤整个目录，再截取最多八个展示候选；本地命中无需逐键请求。目录不可用或非空查询无匹配时，保留原防抖搜索接口，并将结果更新进已有目录。备用接口本身也先搜索所有符合资格的资料，再返回八个匹配结果。本次不新增依赖、WebSocket、频道或环境变量。

上线顺序：应用 `20261028084832_chat_presence_and_directory.sql`，配套部署版本化 broker 配置与应用，再让客户端重连/刷新建立新签名订阅。事件驱动修正不需要新 SQL 迁移。不要开启全局 `join_leave`，避免旧凭证发送未经筛选的元数据。旧 HTTP 调用和消息保持兼容；旧前端包须刷新才能获得新事件行为。回滚应用可保留新增私有列/RPC 和 broker presence。先撤回 broker presence 会使新版应用在线状态不可用。本地修改不包含生产迁移或部署。

2026-10-29 搜索修正：最近参与情况**只影响空 @ 推荐**。首次空查询调用 `GET /api/chat/mentions/users?q=`，取得当前房间 30 天保留期内最近发言的最多八名去重合资格账号，不足八人就显示实际人数。只有这份小列表携带 `lastMessageAt`；目录和关键词结果仅含公开资料。本地及远端关键词排序均为精确名字/UID、前缀、包含，同级按稳定的公开 UID 排序，在线状态与最近发言均不参与。八人限制展示结果，不限制账号搜索范围。

空推荐使用独立的账号会话缓存。既有消息/摘要事件为下一次查询更新最近参与者，关闭面板后仍能更新；在途读取合并新发言。删除消息不会取消或使推荐请求失效，不移除候选账号，也不补齐候选。真实无法恢复的摘要缺口、作者资料未知时沿用原有按需失效处理；连接健康时重开复用缓存，开始一次查询时检查保留期。不使用在线账号补人。一次查询完成后，输入框保留该次账号、顺序和选择，直到输入变化或候选框重开；后台缓存和在线变化不替换当前结果，状态点可以变化。最近发言变化不会重启关键词请求，无匹配响应不会重写未变化的目录。不增加轮询、逐消息目录请求或频道。现有五分钟目录缓存仍可能遗漏之后注册或改名的账号，直到原有刷新/备用搜索触发；本轮没有增加资料同步约定。

升级顺序：先核实已部署的消费方，再依次应用在线状态、`20261029100522_chat_mention_search_separation.sql` 和 `20261029125418_chat_interaction_stability.sql` 迁移，随后部署配套 broker 配置与应用。已发布的 `fbda0c06` 消费方不使用 `lastMessageId`，从该版本升级无需为了此字段安排中间应用部署或强制刷新客户端。只有部署过依赖该字段的开发中间版本，才须先部署修正后的消费方并刷新那些客户端，再用最后一份迁移删除字段及八次逐账号最新消息查询。RPC 名称/参数、HTTP 数组外层、授权、表及已保存消息保持不变。回滚到依赖该字段的中间消费方前须以新迁移恢复对应函数体；回滚到 `fbda0c06` 不需要这一步。不改写已应用的迁移历史。生产操作须针对已明确授权的目标。

## @ 提及（2026-10-28）

已确认的提及在输入框和已发送消息中都标蓝，未选择用户的 `@文字` 仍是普通文字。选中后继续输入不会重新打开同一人的搜索，新输入一个 `@` 才能开始新的选择。输入保留原生 textarea，通过同步宽度、换行和滚动位置的文字着色层显示颜色。他人明确 @ 当前账号的消息整行保留黄色背景和左侧标记，读过、关闭提醒、重新打开或刷新后仍保留；颜色由消息中的账号引用决定，不依赖未读队列。普通文字和 @ 其他人的消息不整行标黄。引用定位可以添加位置描边，不替换黄色底色。

输入 `@` 后，在输入框上方打开紧凑的头像、用户名、UID 列表。空输入仅推荐最近发言的账号；关键词搜索全部合资格资料，包括本人、离线和隐身账号。支持用户名不区分大小写、中文及完整公开 UID，按文字匹配等级、稳定 UID 排序。**8 人仅是展示上限，不限制搜索或目录范围。** 自己 @ 自己不会产生提醒。不提供翻页、查看更多、独立搜索框或分类标题。上下键选择位置稳定的候选行，后台活动不替换默认目标或移动选中账号；Enter/Tab 插入而不发送，Escape 只关闭候选框。选择后保留输入焦点，输入法组词不选人、不发送。面板打开时锁住背景滚动，视口较矮时面板内部滚动。

选中用户后，草稿同时保存 `{userId,start,end}`，位置使用从零开始、右端不包含的 Unicode 码点偏移。只有选中的引用才是提及，单纯粘贴/输入 `@名字` 不会提醒。编辑时保留未改动的引用，删除被改动的引用。`POST /api/chat/messages` 接受可选 `mentions`，文字发送事务 RPC 增加带默认值的末尾 JSON 参数；验证账号资格、有序边界及所选用户名文字。用户改名后可能需要重新选择再发送；已保存消息保留原显示文字及稳定账号 ID。图片发送没有提及参数，图文批次只有文字消息携带自身的提及。引用预览不解析或复制提及到新消息。

保存消息的同一事务为每位不同的非本人收件人保存一条待处理记录，重试不会重复。`GET /api/chat/mentions` 按从旧到新返回前 50 条待处理记录及总数，过滤已删除/超过保留期的消息，不丢弃窗口以外的记录。`PUT` 每次确认 1–50 个消息 ID，只能处理当前账号、当前房间的记录；即使一条较新的 @ 不在前 50 条提醒中，实际看到它也能单独确认。私有表启用 RLS，不授予浏览器角色权限；搜索、读取和确认使用仅服务端可执行的 invoker RPC，权限受限的 definer 辅助函数仅返回 Auth 账号是否非匿名，不暴露 Auth 记录。

工具栏保留普通未读红点，并且只显示一个 **“有人 @ 了你”** 气泡，不带数量；点击后打开留言板并定位第一条待处理提及。面板标题下方一次显示一条提醒：发送者、现有轻量时间、剩余数量、最右侧关闭按钮。提醒从旧到新，新到达的排在后面；点击定位并高亮实际消息，页面位于前台、拥有焦点且实际可见时，只确认看到的消息。关闭仅处理当前一条，不改变滚动位置；下一条继续显示，不自动跳转。定位失败保留提醒，找不到的消息移除并提示“消息已删除”。只打开最新页面不会清空没有看到的旧提醒；普通未读状态独立保留。

既有连接使用当前账号专属的 `chat_mentions:<userId>` 服务端订阅。新提及仍发送 `mentions.changed` 失效通知并读取提醒；确认已读保留同一事件类型，增加 `{roomId, acknowledgedMessageIds}`，HTTP 成功与同账号 WebSocket 事件按 ID 幂等移除。有效完整提醒列表只需一次 PUT、零 GET，自身回声不回读；已不在完整列表中的历史提及无需 PUT。列表超过 50 条、同期失效或确认前已有读取在途时，仍合并必要的补读，旧响应不能恢复已确认提醒。忽略其他房间，写入失败保留提醒，旧格式失效通知仍回读。重连、刷新和打开面板保留持久状态读取；旧客户端可忽略新增字段，沿用原回读流程。不增加频道、outbox、轮询或可见已读策略。

上线顺序：引用/回应迁移后应用 `20261027162659_chat_mentions.sql`，部署 broker 新命名空间和 `client.channel_limit: 3`，最后部署应用。新命名空间与摘要频道一样保留 256 个事件、300 秒。可选字段和默认参数保留旧客户端/RPC 调用兼容；回滚应用可保留新增结构，仍有携带 @ 令牌的客户端连接时不可先撤回 broker 命名空间。本地实现不代表授权生产上线。

## 轻量摘要、未读状态与原生恢复

每个已登录标签页持有一条留言板连接。面板关闭时保持 `chat_activity:main` 摘要订阅；只有打开面板时，才通过订阅令牌订阅完整消息频道 `chat:main`。个人通知保持原有实现，访客不建立这些订阅。

- 登录后先订阅摘要，再读取 `GET /api/chat/activity`。接口只返回 `{latest,latestOther}` 游标，不读取正文、作者资料或未读数量。新增事件携带游标与作者 ID，删除事件携带消息 ID。他人的文字和图片可点亮入口红点；自己的消息与贴纸不触发红点。
- 持久化已读位置使用 `(createdAt,id)`，按账号和房间保存在 `localStorage`。首次使用以当前最新位置初始化，不将旧历史全部标成未读。同一浏览器的其他标签页通过 storage 事件单调推进；不增加跨设备已读同步。只有面板可见、页面有焦点且最新底部已渲染，才推进已读位置。打开旧阅读位置不等于已读；不使用 broker offset 作为已读游标。
- 首次打开先订阅完整消息，再请求 `GET /api/chat/messages?activity=1`。服务端通过一个仅 service_role 可用的 `read_chat_snapshot` RPC，在同一数据库快照中返回最新 50 条和摘要，读取期间缓存实时事件。
- 有有效本地基线且 `recovered:true` 时直接应用 SDK 补发，**不请求历史**。关闭重开保留 Subscription 对象及恢复位置。新增与删除按 ID 幂等应用；瞬时贴纸发布使用 `skip_history:true`，不进入补发。
- 无法恢复或没有有效基线时，仅请求一次最新页，替换旧列表并回到最新位置。保留草稿、待上传内容、失败项及本地已读位置。不再核对保留 ID、拼接断开的旧历史或向后翻页补齐缺口。面板关闭时只恢复摘要，完整消息等打开后加载。
- 关闭保留已加载消息、分页位置和滚动锚点，释放已确认消息的媒体预览，并取消完整消息订阅。待发送附件和上传仍由账号持有。页面隐藏或失焦时暂停已读推进，不主动断开连接。Stamp 播放只要求留言板打开，不要求页面拥有焦点或处于可见状态。页面隐藏时不丢弃新效果，也不清除当前效果或声音；原有时限继续计时，不排队等待回到前台。关闭留言板仍会取消播放。浏览器自身的后台调度和音频策略仍然适用。退出或切换账号时销毁该账号的内存状态和连接。
- 重连期间仍可阅读缓存、跳到列表底部，HTTP 发送成功立即显示。历史读取失败只重试该读取，不拆掉正常的 WebSocket。消息、摘要和在线状态均不轮询。删除当前摘要所指的消息时合并触发一次摘要读取，普通新消息不查询。

两个频道都在 Centrifugo 内存中最多保留 **256 个事件、300 秒**，并强制启用恢复。条数或时间任一超限都会无法恢复，服务重启也会丢失缓存。这用于短暂断线，不提供持久投递保证。数据库已提交但发布失败的变更，要等之后重新取得快照才能看见；outbox 本次仍不实现。

上线顺序为先应用 `20261026072628_chat_activity_and_snapshot.sql`，再更新 broker 配置，最后部署应用。迁移只新增两个固定空 search_path、仅 service_role 可执行的 invoker RPC，不增加表或已读写入。新标签页通过 `POST /api/chat/connection?activity=1` 使用摘要模式；旧请求仍获得原有完整消息服务端订阅。原 before/after 历史接口保持兼容，新客户端不再依赖向后分页恢复。回滚可保留新增 RPC 和历史配置并恢复旧应用。本次只进行本地修改，不包含生产操作。

参考的是 Discord 将非当前会话的轻量活动与正在阅读的完整消息分离、能恢复则补发否则重新初始化的做法，不声称复刻其私有网页协议：[passive sessions](https://discord.com/blog/how-discord-reduced-websocket-traffic-by-40-percent)、[Gateway 恢复](https://docs.discord.com/developers/events/gateway#resuming)、[Centrifugo 恢复](https://centrifugal.dev/docs/server/history_and_recovery)。实现使用现有 Centrifuge SDK。

图片现在同时要求宽 × 高 ≤ 16,777,216、每边 ≤ 16,383，文件上限仍是 20 MiB。静态缩放取总像素与单边缩放系数的最小值，向下取整；合规原文件不变，超限动画明确拒绝。按每像素 4 字节计算，总像素上限对应单个 RGBA 解码表面 64 MiB；解码、画布、编码和动画帧可能同时占用内存。原图在缩小前已解码，因此这不是峰值内存保证。服务端 HEAD 仍校验存储字节/类型，不解码像素。

## 应用契约

消息列表中的文字、图片、用户名、UID 和时间禁用原生选区，复制通过消息菜单完成。图片缩略图同时禁用原生长按弹出操作。输入框草稿仍可选中和编辑，独立图片预览保留浏览器原生图片操作。

消息菜单与弹窗共用兼容的 Radix 焦点及弹层依赖。Esc 只关闭最上层菜单；键盘导航进入菜单项，关闭后焦点回到消息。

界面采用左右分组气泡、共用时间，以及按需出现的复制/删除/管理菜单。自己的消息在每组开头于右侧显示头像，不显示用户名和 UID；连续消息和待发送消息保留头像列的空位。他人的头像和 UID 样式复用评论区。表情选择和渲染沿用评论区，仍将现有短码存入文字字段并按原始字符计数；纯表情消息沿用大表情展示。输入区提供独立图片上传，瞬时 stamp 使用实际发送、额度及广播链路，见[执行计划](realtime-message-board-plan.zh-CN.md#stamp-发送与播放2026-10-24)。使用表情不增加资料、权限或数据库读取，打开聊天预加载共享 stamp 目录及通用素材，具体媒体按需读取。离开最新消息底部或还有较新消息未加载时，显示回到最新消息的悬浮按钮。

未登录及登录状态未确认时隐藏入口，不加载聊天界面/SDK，不请求连接凭证或历史。已登录的非匿名账号可读取和发送；聊天不再另外区分邮箱验证状态。登录、注册及历史账号兼容流程保持原样。服务端仍验证 Auth 凭证并拒绝匿名身份，浏览器不能伪造作者。作者可以删除自己的消息；`user_roles.role = 'chat_moderator'` 可以删除消息及管理禁言。禁言保留查看和删除自己的消息的能力。

每条最多 1,000 个 Unicode 码点，输入计数/截断复用评论区，首尾空白参与计数，提交时 trim，纯空白不发送。历史每页 50 条，使用微秒精度的 `(createdAt,id)` 游标。每账号从本轮首条成功发送开始计时 60 秒，最多 20 条，允许连续发送；不同标签页/设备共享计数。这是固定轮次，不是严格滑动窗口。重试不重复扣次数，保存失败不计数，删除不退款；保存成功但广播失败仍计数。删除清空正文并排除历史，请求 ID 保留到 30 天过期，防止重试复活。

事件携带标识、时间、正文和简短作者展示字段。头像由既有头像组件及资源缓存提供，不逐条请求资料，也不传输图片二进制、装饰、权限或邮箱。消息 UUID 标识已保存记录，请求 UUID 保证发送重试不产生重复记录。

HTTP 响应保持统一成功/错误封装和 no-store。每次文字发送一次 Auth `getUser`，随后一次事务 RPC；不读取 `account_status`，也不调用额外邮箱验证接口。事务仅处理作者资料、幂等请求、禁言、发送计数和消息保存，锁定该账号状态，回复时另外共享锁定原消息。文字常规成功路径新增一条消息并更新一次用户状态，状态行首次使用时创建。图片授权和发布使用下文的两阶段流程。不扫描历史消息计算发送额度，不定时清零，也不轮询限额。读取和连接凭证校验 claims；签名模式可能使 SDK 访问 Auth。原评论权限保持不变。

JWT 签发地址校验优先使用 `NEXT_PUBLIC_SUPABASE_URL`，未配置时才回退到 `SUPABASE_URL`，与全站账号鉴权一致。服务端客户端发出网络请求仍优先使用 `SUPABASE_URL`，因此可通过内部地址访问，同时接受公开地址签发的凭证。

变更提交后返回保存结果，使用 Next.js `after()` 分别向完整消息与摘要频道发布一次；每次发布超时两秒，使用事件类型与消息 ID 去重。贴纸只发布到完整频道且跳过历史。失败只记录脱敏日志，不将已保存操作变成失败。本次没有 outbox、数据库消费者或持久重试。

客户端先订阅并缓冲事件，再取得首次快照。后续优先使用原生历史恢复；仅无法恢复或没有有效基线时重新读取。完整规则见本文首节。

输入区允许通过选图或粘贴累计最多十个文件，正在处理的文件也计入；超出剩余名额时添加可容纳的部分，并提示未添加的文件名。图片在浏览器 Worker 中逐张处理，不访问服务端。预览右上角提供移除操作，共用一个发送按钮，提交图片后接可选的文字。接受提交时整批立即进入待发送列表并清空这份草稿；图片依次保存，最后保存同批文字，之后单独提交的文字不必等待这批图片。批次标识只存在于客户端内存，不进入 API 或数据库。

图片确认时，一次状态更新同时移除待发送条目并加入已保存消息。面板可见时，发送方继续用原本的 Blob 地址显示、复制和预览图片，不立即重新读取 CDN 副本；上传任务及凭证单独释放。这些地址归属已保留消息，重复确认和原生恢复不会提前释放；消息因删除、无法恢复后的快照替换、关闭面板或切换账号而离开保留集合时释放。关闭后才完成的上传不保留已确认预览。重新打开历史和其他客户端正常使用 CDN 地址，不改变 API 或数据库字段。

某张图片失败后，该图片及同批尚未发送的条目分别保留为可重试状态，尚未尝试的内容提示“未发送”。每条旁边的红色圆形感叹号仅重试选中的条目，复用请求 UUID 和已完成的上传；原生悬停提示及辅助技术描述提供原因，右键菜单可移除失败图片或文字，不访问服务端。手动重试可能改变最终顺序；正在处理的条目显示小型加载指示。确认响应直接更新画面，历史读取期间同时缓冲确认事件以避免旧快照覆盖它。失败不覆盖新草稿；限速、禁言、认证或网络失败时保留未发送内容，不自动离线补发。每张成功保存的图片和每条文字分别计入既有发送额度。

关闭面板保留已加载消息、分页、滚动锚点和草稿，只取消完整消息订阅并释放已确认媒体预览。隐藏页面不主动断连；退出和切换账号清理内存。已读游标单独保存在本机。

业务 API fetch 最多等待 30 秒，图片直传 PUT 最多等待五分钟。发送超时进入现有失败/手动重试状态，复用原请求 UUID，并释放正在等待的队列，不无限挂起。PUT 响应丢失仍沿用条件 PUT/HEAD 恢复，不增加轮询或自动投递重试。

已保存消息列表使用 memo 隔离草稿输入更新；自己的正常实时回显只应用一次，历史同步期间的提前确认仍保留缓冲合并路径。

有界删除标记用于拦截迟到的旧 HTTP 响应。超过 1,000 个标记时进行一次同步并取消旧请求，合并后压缩到 500 个，避免后续每删一条就查询一次。这属于事件触发维护，不是轮询。

已发送和发送失败的消息共用“复制”操作。文字复制正文，图片复制可粘贴的图像，不是网址文字。剪贴板路径使用 PNG 表示兼容图片复制，不要求浏览器直接支持原文件 MIME 类型；这个剪贴板表示可能不保留动画，但不改变上传文件或聊天中的播放。失败图片和仍有本地预览的已确认消息复用 Blob，其余已发送图片按需直接从公开 CDN 读取；复制不增加业务 API、数据库请求或存储写入。成功后静默关闭菜单，失败留在菜单内，输入区上方不显示通用提示。

图片菜单另提供“另存为”。支持 `showSaveFilePicker` 时，点击后先打开系统保存窗口，再读取图片；取消就结束，不读取或继续下载。选定位置后，把本地 Blob 或 CDN 原文件字节写入所选文件；写入失败则中止，不再额外触发下载。不支持该窗口的触屏设备把原格式 File 交给系统分享面板；不支持分享或点击授权已过期时，打开现有图片预览，供浏览器原生长按操作，取消分享则直接结束。相册操作由浏览器和系统提供。其他浏览器沿用普通下载，复用本地 Blob URL，或为 CDN 文件创建并释放临时下载地址。整个过程不转码、压缩或重新上传，GIF/WebP/APNG 动画保持。建议文件名为 image.jpg/png/webp/gif。页面不添加保存中/成功/失败/重试界面，不增加业务 API、数据库请求或远端存储写入。已发送及失败消息菜单统一显示“删除”，失败内容只删除本地待发送条目。

聊天图片及其预览从首次显示就使用匿名 CORS，避免后续复制/保存读取到缺少跨域响应头的浏览器缓存。地址使用固定的 `?cors=1` 版本，一次性绕开修复前的浏览器缓存；对象键和文件字节不变，长期 HTTP 缓存保持。关闭消息菜单把焦点交回消息；发送消息、stamp 或删除后不主动聚焦输入框。按 Enter 发送保留输入框已有焦点。长按图片松手时不再同时打开图片预览。手机端外层不透明弹层持续覆盖布局区域，内部会话根据实际可视区域的高度和偏移调整，让输入栏位于键盘上方，同时不露出后面的页面。聊天表单和输入框关闭自动填充，但浏览器原生键盘工具条仍由浏览器控制。

已发送和待发送图片（包括失败图片）均可点开共用大图查看器。待发送图片复用本地 Blob，随对应消息卸载，不另行上传或发起业务请求。消息上长按保留聊天操作，大图放行浏览器原生图片菜单。触屏事件留在图片上，鼠标真正拖动后才捕获；出现原生菜单时停止当前手势，但不阻止浏览器动作。点击图片本身不关闭，点击空白背景、关闭按钮或 Esc 才关闭。这个共用查看器行为也适用于卡面大图。原生图片保存选项由浏览器和系统提供，不另外实现相册写入功能。

## 接入步骤

1. 关闭聊天开关，按既有迁移流程向明确选择且已授权的目标应用 `supabase/migrations/20261012155337_realtime_message_board.sql`，先在隔离本地栈验证。迁移创建两张私有表、仅服务端 RPC 和每十分钟清理最多 1,000 条过期记录的任务，不授予真实账号管理权。此次简化直接修改了尚未发布的迁移草稿；若旧草稿已应用到非临时目标，应另写前向迁移，不能静默改写该目标历史。
   随后应用增量迁移 `20261023205032_chat_sending_and_query_cleanup.sql`，再部署配套应用并启用聊天。增量迁移保留消息和禁言，替换计数字段，移除 viewer 的 `emailVerified`，合并作者查询；旧聊天构建不能继续搭配新 RPC。
2. 使用 **Centrifugo 6.9.7** 和[仓库配置](../deploy/chat/centrifugo.json)。浏览器 SDK **centrifuge 5.7.4**、签名库 **jose 6.2.12** 保持固定。首期单实例 memory engine，启用有界内存历史恢复，不连接 PostgreSQL。[官方频道说明](https://centrifugal.dev/docs/server/channels)将历史缓存作为可选能力。
3. 配置 Centrifugo 进程：
   - `CENTRIFUGO_CLIENT_TOKEN_HMAC_SECRET_KEY`：与应用 `CHAT_TOKEN_SECRET` 相同的随机密钥，至少 32 字节。
   - `CENTRIFUGO_HTTP_API_KEY`：与应用 `CHAT_PUBLISH_API_KEY` 相同，独立于签名密钥。
   - `CENTRIFUGO_CLIENT_ALLOWED_ORIGINS`：空格分隔的精确站点 origin，不使用通配符。
4. 执行 `centrifugo checkconfig --config deploy/chat/centrifugo.json`，再由主机既有服务管理方式启动。两个端口绑定回环地址，仅将 8000 的 `/connection/websocket` 通过 WSS 代理，支持 WebSocket upgrade，空闲超时长于心跳。9000 提供私有发布 API、健康检查和指标，不得经公网代理暴露。管理 UI 保持关闭。
5. 配置应用：
   - `CHAT_TOKEN_SECRET` 和 `CHAT_WEBSOCKET_URL`；生产使用 WSS，本地允许 `ws://localhost:8000/connection/websocket`。
   - `CHAT_PUBLISH_URL=http://127.0.0.1:9000/api/publish` 和 `CHAT_PUBLISH_API_KEY`，仅服务端可见。
   - 目标验证通过后启用运行时 `CHAT_ENABLED=true`，以 `NEXT_PUBLIC_CHAT_ENABLED=true` 重新构建。两者默认 false。

构建和运行时都需设置 `CHAT_WEBSOCKET_URL`，启用构建将其 origin 加入既有 CSP report-only 连接策略。秘密配置仅服务端使用，不写日志。每连接发送队列限制为 2 MiB，慢客户端超限会断开。压缩暂不启用；队列配置和本地冒烟测量均不能证明主机承载能力。

## 图片接入与发布

应用前向迁移 `20261024065425_chat_images.sql`。旧文字 RPC 签名兼容；新图片 RPC 和授权 RPC 只允许 service_role，浏览器仍不能访问私有表。新字段由历史查询一次返回，UUID、分页索引和清理任务不变。新版本部署后再配置图片上传，旧打开页面需要刷新后才能显示图片。

服务端设置 `CHAT_R2_ENDPOINT`、`CHAT_R2_BUCKET`（默认 `cdn`）、`CHAT_R2_ACCESS_KEY_ID`、`CHAT_R2_SECRET_ACCESS_KEY`。使用只覆盖公开桶的专用读写凭证。`NEXT_PUBLIC_SITE_ASSET_CDN_BASE_URL` 继续提供浏览器公开读取域名；服务器 HEAD 走私有 S3 API，文件上传/下载均不经网站服务器。凭证签名复用 `CHAT_TOKEN_SECRET`，使用独立 issuer/audience，与 WebSocket token 不互通。

在明确授权的公开桶上合并以下配置，保留其他既有规则：

- CORS：AllowedOrigins 为真实网站 origin；AllowedMethods 为 PUT 和 GET；AllowedHeaders 为 `Content-Type`、`Cache-Control`、`If-None-Match`；MaxAgeSeconds 可设为 3600。浏览器自动产生被签名的 Content-Length，JS 不手动设置该头。公开 CDN 的 GET 响应也必须允许网站 origin，供“复制图片”读取像素；仅能正常显示图片不代表具有这个权限。
- 生命周期：仅匹配 `user/images/temporary/`，Expiration Days 为 31。R2 异步回收，不承诺精确秒级删除。
- 图片头：`Cache-Control: public, max-age=31536000, immutable`；同路径只允许首次写入。公开域名缓存规则应尊重该策略。

`POST /api/chat/images/upload` 接收 clientRequestId 和图片元数据，合并检查禁言/上传额度并返回 PUT 地址、必要请求头、发布凭证。`POST /api/chat/images` 接收同一 clientRequestId 和凭证，验证 HEAD 后在一次 RPC 中去重、检查禁言及共享消息额度、保存记录，再调用现有广播。PUT 响应丢失时，重试遇到 412 后进入 HEAD 确认；保存失败时保留上传结果，不再次 PUT。超过凭证有效期的待发送项需移除后重新选择。

正常文件保留原字节及其中的元数据；超限静态图重新编码为 WebP（浏览器不支持时验证实际 PNG 输出）。动图不转码。首期不生成缩略图或存储额外原图，不新增上传表、定时扫描或定时客户端检查。

上线前必须在目标桶验证真实浏览器 PUT、CORS、签名长度/类型不可修改、条件覆盖被拒绝，以及公开 CDN 的响应头。单元测试的 SDK 签名和受控浏览器响应不能替代这项检查。回退时先停用图片上传；数据库字段保持，回退到纯文字客户端会无法显示已存图片。

Stamp 发布还需先应用 `20261024124049_chat_stamps.sql` 再部署匹配的应用。房间每秒五次的 stamp 闸门要求一个 Next.js 发布进程，不可让多个 worker/副本各计五次。通用素材须先由 assets-builder 发布。Stamp 不进入消息表、历史、重放或重试路径。

### R2 控制台配置

在 Cloudflare 的 R2 页面选择现有公开 CDN 桶。进入 **Settings > CORS policy**，保留原有规则，再加入网站的准确来源，允许 `PUT`、`GET`，请求头允许 `Content-Type`、`Cache-Control`、`If-None-Match`，可设置 `MaxAgeSeconds: 3600`。参见 [CORS 配置](https://developers.cloudflare.com/r2/buckets/cors/)。先用新上传的 URL 验证，避免旧缓存中的 CORS 响应头干扰。

进入 **Settings > Object lifecycle rules**，新增启用的规则：准确前缀 `user/images/temporary/`，**31 天后删除对象**。保留其他规则，不要将前缀留空，否则会影响桶中无关资源。不需要存储等级转换，也不需要应用定期扫描对象。参见[对象生命周期](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)。

可复用已授权该公开桶的 **Object Read & Write** 凭据；没有可用凭据时，再从 **R2 > Manage API tokens** 创建。将 **Access Key ID** 和 **Secret Access Key** 写入服务器的 `CHAT_R2_ACCESS_KEY_ID` 和 `CHAT_R2_SECRET_ACCESS_KEY`；这里需要的是 S3 凭据，不是 API Token 字符串。`CHAT_R2_ENDPOINT` 填该账号的 S3 endpoint，`CHAT_R2_BUCKET` 填桶名。正常图片操作不要求另建 Token 或获得桶管理权限。参见 [S3 配置](https://developers.cloudflare.com/r2/get-started/s3/)。

若构建时已配置 endpoint，补充凭据后只需重启应用；更换 endpoint 还需重新构建浏览器 CSP。图片继续使用现有公开自定义域名，无需开启 `r2.dev`。正式启用图片发送前，验证真实浏览器上传、显示、复制、原格式保存及禁止覆盖同名对象。

## 房间范围与有界资源（2026-10-25）

先应用 `20261024162353_chat_rooms_and_bounded_retention.sql`，再部署对应应用。迁移增加 `messages.room_id NOT NULL DEFAULT 'main'`，保留已有消息的所有原字段，并将正常消息分页索引替换为 `(room_id, created_at DESC, id DESC) WHERE deleted_at IS NULL`。独立的时间清理索引保留，用于跨房间统一清理。房间标识为 1–64 位小写 ASCII 字母、数字、下划线或连字符，以字母或数字开头；暂不增加房间资料表。

连接、历史、文字/图片、上传和 stamp HTTP 接口接受可选的 `roomId` 查询参数；省略时为 `main`，目前只开放 `main`。未知房间在聊天 RPC 或 R2 操作前拒绝。私有读取、保存、删除 RPC 接收 `p_room_id`，为旧调用保留默认 `main`。迁移替换旧签名，避免 PostgREST 出现重载歧义，并重新保留仅 service_role 可执行的权限。删除同时匹配消息 UUID 与房间。`(user_id, client_request_id)` 仍在账号范围内唯一；同一请求改到别的房间会冲突，包括已经删除的消息。

服务端按 `chat:<roomId>` 得到频道，连接凭证只授权所选频道。连接响应增加 `channel`，客户端据此过滤订阅与广播；兼容旧响应时默认 `chat:main`。广播保持现有载荷，不在每条消息中重复房间字段。文字、图片、删除和瞬时 stamp 都使用服务端确认的同一房间。界面仍只打开一个房间；房间切换及私密访问规则是后续独立功能。禁言及个人额度仍按账号统一计算，每秒五个 stamp 的闸门仍由单个发布进程共享。

清理先固定最多 1,000 个过期 ID，再通过 `DELETE USING` 仅删除这些记录，保留 `FOR UPDATE SKIP LOCKED`。每十分钟一次、保留三十天的规则不变，不为每个房间增加任务或数据库往返。回滚应用时保留新列及新 RPC 签名；省略房间参数仍会进入 `main`。

音效与动画图集只保留进行中的加载记录，成功或失败后立即移除；应用不缓存已完成的音频字节、解码缓冲区或图集图片对象。音频预加载只预热浏览器 HTTP 缓存，不解码也不创建 AudioContext；实际播放时复用 HTTP 缓存并按需解码。正在播放的声音和显示的动画保留所需资源，声音结束或取消时断开节点并清空其 buffer。通用图片预加载也不再保存在全局数组中。浏览器自行管理 HTTP 缓存的内存/磁盘位置和垃圾回收时机。目录/元数据缓存、待发送图片草稿、评论/卡片的单音效行为及 stamp 独立取消保持不变。

共享音效上下文同时恢复 interrupted 和 suspended 状态，已关闭的上下文重新创建。聊天独立音效先取得音频会话，再等待异步恢复，等待范围限于当前效果的可开始播放期限，取消时立即结束。缓存音频先读完也不会因此被丢弃。浏览器等待新的用户播放手势时，不排队补播已过期的 stamp。不会引入常驻音频缓存，也不改变音乐播放器策略。

提前解除禁言不广播状态更新：已打开的客户端可能等到续凭证或本地截止时间才恢复。这是已接受的产品限制，不再列为待修项。

## 当前数据库结构与读写开销

五份聊天迁移最终保留两张私有表。下表描述最终结构，不包含已被替代的三秒间隔和邮箱验证实现。

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `chat_private.messages` | `id uuid`、`user_id uuid`、`client_request_id uuid`、`room_id text`、`created_at timestamptz`、`deleted_at timestamptz?` | 消息标识、作者、房间归属、请求去重、分页及保留期 |
| 同表 | `content text?` | 文字及表情短码，最多 1,000 个码点 |
| 同表 | `image_key text?`、`image_width integer?`、`image_height integer?`、`image_bytes integer?`、`image_content_type text?` | 只存图片元信息，文件在 R2；hash 从 key 提取 |
| `chat_private.user_state` | `user_id uuid`、`muted_until timestamptz?`、`moderated_by uuid?`、`moderated_at timestamptz?` | 发言或受管理的账号各一行 |
| 同表 | `send_window_started_at timestamptz?`、`send_count smallint` | 文字与图片共用的固定窗口额度 |
| 同表 | `upload_window_started_at timestamptz?`、`upload_count smallint` | 图片上传授权额度，独立于消息保存 |
| 同表 | `stamp_window_started_at timestamptz?`、`stamp_count smallint` | 瞬时 stamp 独立额度 |

消息约束只允许三种状态：有文字的正常消息、有图片的正常消息、正文及图片字段均清空的已删除记录。图片元信息限制支持的 MIME、20 MiB、宽高 1–16,383、总像素不超过 16,777,216，以及绑定账号/请求的对象路径。像素元信息由浏览器处理提供；服务端 HEAD 检查已存对象的长度、类型和缓存头，不解码图片。三个计数均限制 0–20。账号外键复用 profiles，删除账号时级联删除；删除管理员账号时 moderated_by 置空。

消息表有四个索引：消息主键、`(user_id,client_request_id)` 唯一索引、正常消息的 `(room_id,created_at DESC,id DESC)` 分页索引，以及 created_at 清理索引。用户状态表有账号主键和 moderated_by 非空索引，后者服务于外键。现有复合唯一索引已经支持按消息作者定位，不需要再加一份单独的作者索引。

两表均启用 RLS，客户端没有私有 schema/表访问权限。十一个公开聊天 RPC 使用调用者权限运行，只授权 service_role。作者展示和管理员权限来自现有 profiles、user_roles。没有另建聊天资料、上传记录、在线状态、回执、stamp 历史或 outbox 表。

| 操作 | 业务 RPC 次数 | 正常数据库写入 | R2 操作 |
| --- | --- | --- | --- |
| 登录并建立摘要 | Viewer + 摘要：2 | 无 | 无 |
| 首次打开 / 无法恢复时打开 | 消息与摘要合并快照：1 | 无 | 按需读取缓存/CDN |
| 正常恢复 / 有效恢复的重开 | 0 | 无 | 按需读取缓存/CDN |
| 接收广播 | 0 | 无 | 仅未缓存媒体，直接访问 CDN |
| 发文字 | 1 | 插入消息 + 更新账号计数 | 无 |
| 发图片 | 上传授权 + 保存，共 2 次 | 更新上传计数，随后插入消息 + 更新发送计数 | 浏览器 PUT + 服务端 HEAD；观看走 CDN |
| 发 stamp | 1 | 只更新 stamp 计数 | 私有 Master 校验复用缓存；媒体由客户端直接读取 |
| 删除消息 | 1 | 清空正文/图片字段并设置 deleted_at | 不立即删对象或清缓存 |
| 禁言/解除禁言 | 1 | 新建或更新一行用户状态 | 无 |
| 续连接凭证 | 1 | 无 | 无 |

RPC 次数指网络请求，不是 SQL 语句条数；写事务内部仍执行账号、状态、请求 ID 的索引查询。第一次使用才创建用户状态行。每次文字/stamp 写入有一次 Auth getUser 请求；图片授权和完成各一次。读取和连接签发使用 getClaims，非对称签名可复用公钥缓存做本地验证，对称签名可能访问 Auth。聊天不另查邮箱验证状态。

每秒五次的房间闸门限制广播，不等于每秒只执行五次 HTTP/Auth/数据库操作：通过个人额度但被房间闸门丢弃的事件，仍消耗个人次数。这维持已确定的计数语义。锁按账号隔离，不会让所有人等待同一个房间计数行。

凭证获取失败采用最长 30 秒的退避；快照读取失败独立重试，不中断正常连接。SDK 负责网络重连；终止断开不无限重试，用户重新打开可以再连接。隐藏页面不取消连接，健康连接无定期查询。
