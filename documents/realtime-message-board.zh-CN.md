# 即时留言板

English version: [realtime-message-board.md](realtime-message-board.md).

本地实现默认关闭。生产迁移、账号授权和部署需要另行明确操作范围。见[执行计划](realtime-message-board-plan.zh-CN.md)和[验证记录](realtime-message-board-validation.zh-CN.md)。

## 应用契约

消息列表中的文字、图片、用户名、UID 和时间禁用原生选区，复制通过消息菜单完成。图片缩略图同时禁用原生长按弹出操作。输入框草稿仍可选中和编辑，独立图片预览保留浏览器原生图片操作。

消息菜单与弹窗共用兼容的 Radix 焦点及弹层依赖。Esc 只关闭最上层菜单；键盘导航进入菜单项，关闭后焦点回到消息。

界面采用左右分组气泡、共用时间，以及按需出现的复制/删除/管理菜单。自己的身份不显示，他人的头像和 UID 样式复用评论区。表情选择和渲染沿用评论区，仍将现有短码存入文字字段并按原始字符计数；纯表情消息沿用大表情展示。输入区提供独立图片上传，瞬时 stamp 使用实际发送、额度及广播链路，见[执行计划](realtime-message-board-plan.zh-CN.md#stamp-发送与播放2026-10-24)。使用表情不增加资料、权限或数据库读取，打开聊天预加载共享 stamp 目录及通用素材，具体媒体按需读取。回到最新消息的悬浮按钮只在需要时出现，包括向前分页后内存窗口已不包含最新一页的情况。

未登录及登录状态未确认时隐藏入口，不加载聊天界面/SDK，不请求连接凭证或历史。已登录的非匿名账号可读取和发送；聊天不再另外区分邮箱验证状态。登录、注册及历史账号兼容流程保持原样。服务端仍验证 Auth 凭证并拒绝匿名身份，浏览器不能伪造作者。作者可以删除自己的消息；`user_roles.role = 'chat_moderator'` 可以删除消息及管理禁言。禁言保留查看和删除自己的消息的能力。

每条最多 1,000 个 Unicode 码点，输入计数/截断复用评论区，首尾空白参与计数，提交时 trim，纯空白不发送。历史每页 50 条，使用微秒精度的 `(createdAt,id)` 游标。每账号从本轮首条成功发送开始计时 60 秒，最多 20 条，允许连续发送；不同标签页/设备共享计数。这是固定轮次，不是严格滑动窗口。重试不重复扣次数，保存失败不计数，删除不退款；保存成功但广播失败仍计数。删除清空正文并排除历史，请求 ID 保留到 30 天过期，防止重试复活。

事件携带标识、时间、正文和简短作者展示字段。头像由既有头像组件及资源缓存提供，不逐条请求资料，也不传输图片二进制、装饰、权限或邮箱。消息 UUID 标识已保存记录，请求 UUID 保证发送重试不产生重复记录。

HTTP 响应保持统一成功/错误封装和 no-store。每次文字发送一次 Auth `getUser`，随后一次事务 RPC；不读取 `account_status`，也不调用额外邮箱验证接口。事务仅处理作者资料、幂等请求、禁言、发送计数和消息保存，锁只作用于该账号。文字常规成功路径新增一条消息并更新一次用户状态，状态行首次使用时创建。图片授权和发布使用下文的两阶段流程。不扫描历史消息计算发送额度，不定时清零，也不轮询限额。读取和连接凭证校验 claims；签名模式可能使 SDK 访问 Auth。原评论权限保持不变。

JWT 签发地址校验优先使用 `NEXT_PUBLIC_SUPABASE_URL`，未配置时才回退到 `SUPABASE_URL`，与全站账号鉴权一致。服务端客户端发出网络请求仍优先使用 `SUPABASE_URL`，因此可通过内部地址访问，同时接受公开地址签发的凭证。

修改 RPC 提交后，网站先返回已保存结果，再通过 Next.js `after()` 在响应后将事件发送至 Centrifugo 私有 HTTP API。仍只尝试一次、超时两秒，发送者不再等待这次广播尝试。HTTP 错误、API 错误和超时只记录脱敏日志，不把已保存的修改报告成失败。没有 outbox、数据库消费者、LISTEN 连接或后台发布重试。广播失败时，其他在线客户端可能要到重连、重新打开或刷新后才能看见变化，这是接受的投递边界。

客户端先订阅，再读取最新一页，读取期间缓冲实时事件。首次打开、重新打开和每次重连均读取一次最新历史。关闭 Centrifugo 历史缓存回放：用数据库当前记录恢复画面，避免旧创建事件将已删除消息重新带回。SDK 心跳和自动重连保留，没有业务序号补洞或定时历史检查。

输入区允许通过选图或粘贴累计最多十个文件，正在处理的文件也计入；超出剩余名额时添加可容纳的部分，并提示未添加的文件名。图片在浏览器 Worker 中逐张处理，不访问服务端。预览右上角提供移除操作，共用一个发送按钮，提交图片后接可选的文字。接受提交时整批立即进入待发送列表并清空这份草稿；图片依次保存，最后保存同批文字，之后单独提交的文字不必等待这批图片。批次标识只存在于客户端内存，不进入 API 或数据库。

图片确认时，一次状态更新同时移除待发送条目并加入已保存消息。面板可见时，发送方继续用原本的 Blob 地址显示、复制和预览图片，不立即重新读取 CDN 副本；上传任务及凭证单独释放。这些地址只归属有界消息窗口及待显示尾部，重复确认和断线历史合并不会提前释放，删除、移出保留范围、关闭面板或切换账号时释放。关闭后才完成的上传不保留已确认预览。重新打开历史和其他客户端正常使用 CDN 地址，不改变 API 或数据库字段。

某张图片失败后，该图片及同批尚未发送的条目分别保留为可重试状态，尚未尝试的内容提示“未发送”。每条旁边的红色圆形感叹号仅重试选中的条目，复用请求 UUID 和已完成的上传；原生悬停提示及辅助技术描述提供原因，右键菜单可移除失败图片或文字，不访问服务端。手动重试可能改变最终顺序；正在处理的条目显示小型加载指示。确认响应直接更新画面，历史读取期间同时缓冲确认事件以避免旧快照覆盖它。失败不覆盖新草稿；限速、禁言、认证或网络失败时保留未发送内容，不自动离线补发。每张成功保存的图片和每条文字分别计入既有发送额度。

关闭浮层会断开连接，将当前窗口与待显示尾部合并后，仅保留最近收到的 50 条消息记录。已确认图片释放本地文件/预览，只保留持久化元数据。文字/图片草稿和待发送状态独立保留，已提交请求正常收尾，迟到确认仍遵守关闭后的 50 条上限。重新打开立即显示保留记录，再由一次最新历史响应替换，不把旧缓存合并回最新历史。首次加载、重连、同步及读取更早历史统一使用顶部居中的现有转圈，不显示重连文字条。图片准备由账号浮层持有，关闭面板保留所选文件、正在进行的处理及预览地址，不重复处理或上传。发送/移除草稿时释放预览；退出/切换账号终止图片处理、释放草稿地址并销毁全部保留状态，停止未发请求，忽略迟到结果。记录和草稿只在内存中保留，刷新页面后不保留。页面隐藏时断开但保留画面，恢复可见时重连并刷新。连接 JWT 最长一小时，且不晚于授权 access token；正常续期不重拉历史、不重建连接。

业务 API fetch 最多等待 30 秒，图片直传 PUT 最多等待五分钟。发送超时进入现有失败/手动重试状态，复用原请求 UUID，并释放正在等待的队列，不无限挂起。PUT 响应丢失仍沿用条件 PUT/HEAD 恢复，不增加轮询或自动投递重试。

300 条内存窗口因实时或缓冲消息裁掉旧记录时，将历史游标同步到第一条保留记录，原先没有游标也会补上，保证仍可读取被裁掉的历史；这不额外发起读取。已保存消息列表使用 memo 隔离草稿输入更新；自己的正常实时回显只应用一次，历史同步期间的提前确认仍保留缓冲合并路径。

有界删除标记用于拦截迟到的旧 HTTP 响应。超过 1,000 个标记时进行一次同步并取消旧请求，合并后压缩到 500 个，避免后续每删一条就查询一次。这属于事件触发维护，不是轮询。

已发送和发送失败的消息共用“复制”操作。文字复制正文，图片复制可粘贴的图像，不是网址文字。剪贴板路径使用 PNG 表示兼容图片复制，不要求浏览器直接支持原文件 MIME 类型；这个剪贴板表示可能不保留动画，但不改变上传文件或聊天中的播放。失败图片和仍有本地预览的已确认消息复用 Blob，其余已发送图片按需直接从公开 CDN 读取；复制不增加业务 API、数据库请求或存储写入。成功后静默关闭菜单，失败留在菜单内，输入区上方不显示通用提示。

图片菜单另提供“另存为”。支持 `showSaveFilePicker` 时，点击后先打开系统保存窗口，再读取图片；取消就结束，不读取或继续下载。选定位置后，把本地 Blob 或 CDN 原文件字节写入所选文件；写入失败则中止，不再额外触发下载。不支持该窗口的触屏设备把原格式 File 交给系统分享面板；不支持分享或点击授权已过期时，打开现有图片预览，供浏览器原生长按操作，取消分享则直接结束。相册操作由浏览器和系统提供。其他浏览器沿用普通下载，复用本地 Blob URL，或为 CDN 文件创建并释放临时下载地址。整个过程不转码、压缩或重新上传，GIF/WebP/APNG 动画保持。建议文件名为 image.jpg/png/webp/gif。页面不添加保存中/成功/失败/重试界面，不增加业务 API、数据库请求或远端存储写入。已发送及失败消息菜单统一显示“删除”，失败内容只删除本地待发送条目。

聊天图片及其预览从首次显示就使用匿名 CORS，避免后续复制/保存读取到缺少跨域响应头的浏览器缓存。地址使用固定的 `?cors=1` 版本，一次性绕开修复前的浏览器缓存；对象键和文件字节不变，长期 HTTP 缓存保持。关闭消息菜单把焦点交回消息；发送消息、stamp 或删除后不主动聚焦输入框。按 Enter 发送保留输入框已有焦点。长按图片松手时不再同时打开图片预览。手机端外层不透明弹层持续覆盖布局区域，内部会话根据实际可视区域的高度和偏移调整，让输入栏位于键盘上方，同时不露出后面的页面。聊天表单和输入框关闭自动填充，但浏览器原生键盘工具条仍由浏览器控制。

已发送和待发送图片（包括失败图片）均可点开共用大图查看器。待发送图片复用本地 Blob，随对应消息卸载，不另行上传或发起业务请求。消息上长按保留聊天操作，大图放行浏览器原生图片菜单。触屏事件留在图片上，鼠标真正拖动后才捕获；出现原生菜单时停止当前手势，但不阻止浏览器动作。点击图片本身不关闭，点击空白背景、关闭按钮或 Esc 才关闭。这个共用查看器行为也适用于卡面大图。原生图片保存选项由浏览器和系统提供，不另外实现相册写入功能。

## 接入步骤

1. 关闭聊天开关，按既有迁移流程向明确选择且已授权的目标应用 `supabase/migrations/20261012155337_realtime_message_board.sql`，先在隔离本地栈验证。迁移创建两张私有表、仅服务端 RPC 和每十分钟清理最多 1,000 条过期记录的任务，不授予真实账号管理权。此次简化直接修改了尚未发布的迁移草稿；若旧草稿已应用到非临时目标，应另写前向迁移，不能静默改写该目标历史。
   随后应用增量迁移 `20261023205032_chat_sending_and_query_cleanup.sql`，再部署配套应用并启用聊天。增量迁移保留消息和禁言，替换计数字段，移除 viewer 的 `emailVerified`，合并作者查询；旧聊天构建不能继续搭配新 RPC。
2. 使用 **Centrifugo 6.9.7** 和[仓库配置](../deploy/chat/centrifugo.json)。浏览器 SDK **centrifuge 5.7.4**、签名库 **jose 6.2.12** 保持固定。首期单实例 memory engine，不启用历史恢复，不连接 PostgreSQL。[官方频道说明](https://centrifugal.dev/docs/server/channels)将历史缓存作为可选能力。
3. 配置 Centrifugo 进程：
   - `CENTRIFUGO_CLIENT_TOKEN_HMAC_SECRET_KEY`：与应用 `CHAT_TOKEN_SECRET` 相同的随机密钥，至少 32 字节。
   - `CENTRIFUGO_HTTP_API_KEY`：与应用 `CHAT_PUBLISH_API_KEY` 相同，独立于签名密钥。
   - `CENTRIFUGO_CLIENT_ALLOWED_ORIGINS`：空格分隔的精确站点 origin，不使用通配符。
4. 执行 `centrifugo checkconfig --config deploy/chat/centrifugo.json`，再由主机既有服务管理方式启动。两个端口绑定回环地址，仅将 8000 的 `/connection/websocket` 通过 WSS 代理，支持 WebSocket upgrade，空闲超时长于心跳。9000 提供私有发布 API、健康检查和指标，不得经公网代理暴露。管理 UI 保持关闭。
5. 配置应用：
   - `CHAT_TOKEN_SECRET` 和 `CHAT_WEBSOCKET_URL`；生产使用 WSS，本地允许 `ws://localhost:8000/connection/websocket`。
   - `CHAT_PUBLISH_URL=http://127.0.0.1:9000/api/publish` 和 `CHAT_PUBLISH_API_KEY`，仅服务端可见。
   - 目标验证通过后启用运行时 `CHAT_ENABLED=true`，以 `NEXT_PUBLIC_CHAT_ENABLED=true` 重新构建。两者默认 false。

构建和运行时都需设置 `CHAT_WEBSOCKET_URL`，启用构建将其 origin 加入既有 CSP report-only 连接策略。秘密配置仅服务端使用，不写日志。每连接发送队列限制为 2 MiB，慢客户端超限会断开。压缩暂不启用；队列配置和本地冒烟测量均不能证明主机承载能力。

## 验证与维护

- `npm run test:chat`：无需外部服务，覆盖鉴权、输入限制、凭证有效期、响应后广播失败、UUID 重试、超时、草稿清理、分页、生命周期竞态和请求数。CI 运行此套件，并在既有临时数据库任务中将 `realtime_message_board.sql`、`chat_images.sql`、`chat_stamps.sql`、`chat_rooms.sql` 四份聊天 SQL 与账号测试一起执行。
- `npm run test:supabase`：在隔离且已迁移的本地栈检查 SQL 权限、移除邮箱查表、禁言/20 条限额、重试、删除、分页和保留期。
- 设置 `CHAT_TEST_CENTRIFUGO` 为固定版本可执行文件，执行 `npm run test:chat:realtime`。它使用临时密钥及独立回环服务，验证 200 个客户端、发布去重、重连不回放及越权发布拒绝，输出本地延迟和载荷字节数，不代表 TLS 流量或生产承载能力。
- 另设 `CHAT_TEST_DB_CONTAINER` 指向全新、已迁移的临时 `supabase_db_hhwx-chat-verify-<后缀>` 容器，执行 `npm run test:chat:postgres`。生产路由、发布函数、SQL RPC、ChatSession 和真实 SDK/服务共同验证并发发送/禁言、回滚、广播失败后数据库恢复、旧删除恢复及服务重启。Auth 身份使用夹具，RPC 通过本地 psql 执行，不能证明 Auth/PostgREST 接入。脚本要求聊天表为空，拒绝普通本地容器，不使用应用凭证，结束后移除自有夹具和进程。
- 执行相关 typecheck、lint、build 和多语言检查；证据与边界见[验证记录](realtime-message-board-validation.zh-CN.md)。

通过既有日志和指标观察广播失败、重连及历史请求数。没有持久队列或待排空积压；首期不承诺完整离线投递，保留期内的旧消息仍可分页读取。

回退时关闭运行时开关并重新构建隐藏入口。既有凭证最多一小时失效，不晚于授权 access token；需要立即断开时停止 Centrifugo。保留已保存数据，不以删表作为应用回退。保留期任务继续执行，除非另行修改。

部署前仍需验证私有 API 隔离与密钥配置、公网 WSS 路径和真实账号 UI 状态。实例规格、架构、CPU 积分和升级决策属于环境参考，不是验收条件。

## 图片接入与发布

应用前向迁移 `20261024065425_chat_images.sql`。旧文字 RPC 签名兼容；新图片 RPC 和授权 RPC 只允许 service_role，浏览器仍不能访问私有表。新字段由历史查询一次返回，UUID、分页索引和清理任务不变。新版本部署后再配置图片上传，旧打开页面需要刷新后才能显示图片。

服务端设置 `CHAT_R2_ENDPOINT`、`CHAT_R2_BUCKET`（默认 `cdn`）、`CHAT_R2_ACCESS_KEY_ID`、`CHAT_R2_SECRET_ACCESS_KEY`。使用只覆盖公开桶的专用读写凭证。`NEXT_PUBLIC_SITE_ASSET_CDN_BASE_URL` 继续提供浏览器公开读取域名；服务器 HEAD 走私有 S3 API，文件上传/下载均不经网站服务器。凭证签名复用 `CHAT_TOKEN_SECRET`，使用独立 issuer/audience，与 WebSocket token 不互通。

在明确授权的公开桶上合并以下配置，保留其他既有规则：

- CORS：AllowedOrigins 为真实网站 origin；AllowedMethods 为 PUT 和 GET；AllowedHeaders 为 `Content-Type`、`Cache-Control`、`If-None-Match`；MaxAgeSeconds 可设为 3600。浏览器自动产生被签名的 Content-Length，JS 不手动设置该头。公开 CDN 的 GET 响应也必须允许网站 origin，供“复制图片”读取像素；仅能正常显示图片不代表具有这个权限。
- 生命周期：仅匹配 `user/images/temporary/`，Expiration Days 为 31。R2 异步回收，不承诺精确秒级删除。
- 图片头：`Cache-Control: public, max-age=31536000, immutable`；同路径只允许首次写入。公开域名缓存规则应尊重该策略。

`POST /api/chat/images/upload` 接收 clientRequestId 和图片元数据，合并检查禁言/上传额度并返回 PUT 地址、必要请求头、发布凭证。`POST /api/chat/images` 接收同一 clientRequestId 和凭证，验证 HEAD 后在一次 RPC 中去重、检查禁言及共享消息额度、保存记录，再调用现有广播。PUT 响应丢失时，重试遇到 412 后进入 HEAD 确认；保存失败时保留上传结果，不再次 PUT。超过凭证有效期的待发送项需移除后重新选择。

正常文件保留原字节及其中的元数据；超限静态图重新编码为 WebP（浏览器不支持时验证实际 PNG 输出）。动图不转码。首期不生成缩略图或存储额外原图，不新增上传表、定时扫描或定时客户端检查。

上线前必须在目标桶验证真实浏览器 PUT、CORS、签名长度/类型不可修改、条件覆盖被拒绝，以及公开 CDN 的响应头。单元测试的 SDK 签名和受控浏览器响应不能替代这项检查。回退时先停用图片上传；数据库字段保持，回退到纯文字客户端会无法显示已存图片。

Stamp 发布还需先应用 `20261024124049_chat_stamps.sql` 再部署匹配的应用。房间每秒五次的 stamp 闸门要求一个 Next.js 发布进程，不可让多个 worker/副本各计五次。通用素材须先由 assets-builder 发布。Stamp 不进入消息表、历史、重放或重试路径。

### R2 控制台配置

在 Cloudflare 的 R2 页面选择现有公开 CDN 桶。进入 **Settings > CORS policy**，保留原有规则，再加入网站的准确来源，允许 `PUT`、`GET`，请求头允许 `Content-Type`、`Cache-Control`、`If-None-Match`，可设置 `MaxAgeSeconds: 3600`。参见 [CORS 配置](https://developers.cloudflare.com/r2/buckets/cors/)。先用新上传的 URL 验证，避免旧缓存中的 CORS 响应头干扰。

进入 **Settings > Object lifecycle rules**，新增启用的规则：准确前缀 `user/images/temporary/`，**31 天后删除对象**。保留其他规则，不要将前缀留空，否则会影响桶中无关资源。不需要存储等级转换，也不需要应用定期扫描对象。参见[对象生命周期](https://developers.cloudflare.com/r2/buckets/object-lifecycles/)。

可复用已授权该公开桶的 **Object Read & Write** 凭据；没有可用凭据时，再从 **R2 > Manage API tokens** 创建。将 **Access Key ID** 和 **Secret Access Key** 写入服务器的 `CHAT_R2_ACCESS_KEY_ID` 和 `CHAT_R2_SECRET_ACCESS_KEY`；这里需要的是 S3 凭据，不是 API Token 字符串。`CHAT_R2_ENDPOINT` 填该账号的 S3 endpoint，`CHAT_R2_BUCKET` 填桶名。正常图片操作不要求另建 Token 或获得桶管理权限。参见 [S3 配置](https://developers.cloudflare.com/r2/get-started/s3/)。

若构建时已配置 endpoint，补充凭据后只需重启应用；更换 endpoint 还需重新构建浏览器 CSP。图片继续使用现有公开自定义域名，无需开启 `r2.dev`。正式启用图片发送前，验证真实浏览器上传、显示、复制、原格式保存及禁止覆盖同名对象。

## 房间范围与有界资源（2026-10-25）

先应用 `20261024162353_chat_rooms_and_bounded_retention.sql`，再部署对应应用。迁移增加 `messages.room_id NOT NULL DEFAULT 'main'`，保留已有消息的所有原字段，并将正常消息分页索引替换为 `(room_id, created_at DESC, id DESC) WHERE deleted_at IS NULL`。独立的时间清理索引保留，用于跨房间统一清理。房间标识为 1–64 位小写 ASCII 字母、数字、下划线或连字符，以字母或数字开头；暂不增加房间资料表。

连接、历史、文字/图片、上传和 stamp HTTP 接口接受可选的 `roomId` 查询参数；省略时为 `main`，目前只开放 `main`。未知房间在聊天 RPC 或 R2 操作前拒绝。私有读取、保存、删除 RPC 接收 `p_room_id`，为旧调用保留默认 `main`。迁移替换旧签名，避免 PostgREST 出现重载歧义，并重新保留仅 service_role 可执行的权限。删除同时匹配消息 UUID 与房间。`(user_id, client_request_id)` 仍在账号范围内唯一；同一请求改到别的房间会冲突，包括已经删除的消息。

服务端按 `chat:<roomId>` 得到频道，连接凭证只授权所选频道。连接响应增加 `channel`，客户端据此过滤订阅与广播；兼容旧响应时默认 `chat:main`。广播保持现有载荷，不在每条消息中重复房间字段。文字、图片、删除和瞬时 stamp 都使用服务端确认的同一房间。界面仍只打开一个房间；房间切换及私密访问规则是后续独立功能。禁言及个人额度仍按账号统一计算，每秒五个 stamp 的闸门仍由单个发布进程共享。

清理先固定最多 1,000 个过期 ID，再通过 `DELETE USING` 仅删除这些记录，保留 `FOR UPDATE SKIP LOCKED`。每十分钟一次、保留三十天的规则不变，不为每个房间增加任务或数据库往返。回滚应用时保留新列及新 RPC 签名；省略房间参数仍会进入 `main`。

音效与动画图集只保留进行中的加载记录，成功或失败后立即移除；应用不缓存已完成的音频字节、解码缓冲区或图集图片对象。音频预加载只预热浏览器 HTTP 缓存，不解码也不创建 AudioContext；实际播放时复用 HTTP 缓存并按需解码。正在播放的声音和显示的动画保留所需资源，声音结束或取消时断开节点并清空其 buffer。通用图片预加载也不再保存在全局数组中。浏览器自行管理 HTTP 缓存的内存/磁盘位置和垃圾回收时机。目录/元数据缓存、待发送图片草稿、评论/卡片的单音效行为及 stamp 独立取消保持不变。

共享音效上下文同时恢复 interrupted 和 suspended 状态，已关闭的上下文重新创建。聊天独立音效先取得音频会话，再等待异步恢复，等待范围限于当前效果的可开始播放期限，取消时立即结束。缓存音频先读完也不会因此被丢弃。浏览器等待新的用户播放手势时，不排队补播已过期的 stamp。不会引入常驻音频缓存，也不改变音乐播放器策略。

提前解除禁言不广播状态更新：已打开的客户端可能等到重开、续凭证或本地截止时间才恢复。这是已接受的产品限制，不再列为待修项。

## 当前数据库结构与读写开销

五份聊天迁移最终保留两张私有表。下表描述最终结构，不包含已被替代的三秒间隔和邮箱验证实现。

| 表 | 字段 | 用途 |
| --- | --- | --- |
| `chat_private.messages` | `id uuid`、`user_id uuid`、`client_request_id uuid`、`room_id text`、`created_at timestamptz`、`deleted_at timestamptz?` | 消息标识、作者、房间归属、请求去重、分页及保留期 |
| 同表 | `content text?` | 文字及表情短码，最多 1,000 个码点 |
| 同表 | `image_key text?`、`image_width integer?`、`image_height integer?`、`image_bytes integer?`、`image_content_type text?` | 只存图片元信息，文件在 R2；hash 从 key 提取 |
| `chat_private.user_state` | `user_id uuid`、`muted_until timestamptz?`、`moderated_by uuid?`、`moderated_at timestamptz?` | 发言或受管理的账号各一行 |
| 同表 | `send_window_started_at timestamptz?`、`send_count smallint` | 文字与图片共用的固定窗口额度 |
| 同表 | `upload_window_started_at timestamptz?`、`upload_count smallint` | 图片上传授权额度，独立于消息保存 |
| 同表 | `stamp_window_started_at timestamptz?`、`stamp_count smallint` | 瞬时 stamp 独立额度 |

消息约束只允许三种状态：有文字的正常消息、有图片的正常消息、正文及图片字段均清空的已删除记录。图片元信息限制支持的 MIME、20 MiB、宽高 1–4096，以及绑定账号/请求的对象路径。像素元信息由浏览器处理提供；服务端 HEAD 检查已存对象的长度、类型和缓存头，不解码图片。三个计数均限制 0–20。账号外键复用 profiles，删除账号时级联删除；删除管理员账号时 moderated_by 置空。

消息表有四个索引：消息主键、`(user_id,client_request_id)` 唯一索引、正常消息的 `(room_id,created_at DESC,id DESC)` 分页索引，以及 created_at 清理索引。用户状态表有账号主键和 moderated_by 非空索引，后者服务于外键。现有复合唯一索引已经支持按消息作者定位，不需要再加一份单独的作者索引。

两表均启用 RLS，客户端没有私有 schema/表访问权限。九个公开聊天 RPC 使用调用者权限运行，只授权 service_role。作者展示和管理员权限来自现有 profiles、user_roles。没有另建聊天资料、上传记录、在线状态、回执、stamp 历史或 outbox 表。

| 操作 | 业务 RPC 次数 | 正常数据库写入 | R2 操作 |
| --- | --- | --- | --- |
| 打开/重新打开 | 状态 + 最新历史，共 2 次 | 无 | 共享目录/素材按需读取并缓存 |
| 接收广播 | 0 | 无 | 仅未缓存媒体，直接访问 CDN |
| 发文字 | 1 | 插入消息 + 更新账号计数 | 无 |
| 发图片 | 上传授权 + 保存，共 2 次 | 更新上传计数，随后插入消息 + 更新发送计数 | 浏览器 PUT + 服务端 HEAD；观看走 CDN |
| 发 stamp | 1 | 只更新 stamp 计数 | 私有 Master 校验复用缓存；媒体由客户端直接读取 |
| 删除消息 | 1 | 清空正文/图片字段并设置 deleted_at | 不立即删对象或清缓存 |
| 禁言/解除禁言 | 1 | 新建或更新一行用户状态 | 无 |
| 续连接凭证 | 1 | 无 | 无 |

RPC 次数指网络请求，不是 SQL 语句条数；写事务内部仍执行账号、状态、请求 ID 的索引查询。第一次使用才创建用户状态行。每次文字/stamp 写入有一次 Auth getUser 请求；图片授权和完成各一次。读取和连接签发使用 getClaims，非对称签名可复用公钥缓存做本地验证，对称签名可能访问 Auth。聊天不另查邮箱验证状态。

每秒五次的房间闸门限制广播，不等于每秒只执行五次 HTTP/Auth/数据库操作：通过个人额度但被房间闸门丢弃的事件，仍消耗个人次数。这维持已确定的计数语义。锁按账号隔离，不会让所有人等待同一个房间计数行。

初始连接/历史读取临时失败时，现在使用带随机错开的指数退避自动恢复，间隔上限 30 秒；同步成功后结束，关闭、隐藏或销毁时取消。普通网络断线由 SDK 的 connecting 状态继续自动恢复；SDK 最终 disconnected 状态终止应用重试，包括凭证过期后的永久续签拒绝，重新打开可以建立新连接。这是失败后的连接恢复，不是正常连接期间轮询历史，也不自动重发消息。持久消息失败保留自身图标和原生 title，不再使用可能撑宽列表的自定义提示框；输入区上方没有通用失败条或手动重连按钮。
