# Bandori 组曲精确搜索

英文版：[medley-search.md](medley-search.md)

## 摘要

本文规定精确搜索的做法，列出剪枝依赖的不变量，并论证为什么一次正常完成的搜索不会漏掉更优的合法组曲。请先阅读[计分与产品契约](medley-foundation.zh-CN.md)；其中定义了本文使用的卡牌、歌曲、道具配置、分数函数和最终状态。

搜索覆盖每套合法的三队共用区域道具，以及十五张物理卡牌对三个固定歌曲位置的每种合法分配。实际算法是分支定界：分别使用安全的单队分数上界，以及额外考虑物理卡竞争的三队联合分配上界；引擎取各个有效整体上界中的较小值。当剩余组合已经足够小时，改为精确穷举收尾。启发式只改变遍历顺序和当前最高分的质量，不会删除候选。

输入与精确计分以[规则与计分说明](medley-foundation.zh-CN.md)为准。每个有限的剪枝值都必须是正式计分器的上界。如果某个上界可能低于精确分数，这就是错误；应让该优化失效或修正它，不能为了迁就上界而改变计分语义。

对应实现按职责拆分，均位于 `crates/bandori-medley-search/src/`：`exact_score.rs`、`candidate.rs` 结算完整队伍；`fast_upper.rs`、`upper_bound.rs` 构造单队数值上界；`joint_upper.rs` 求解放宽后的三队联合分配；`search.rs` 负责穷尽划分、可回退状态、局部连接和最终完成状态。

## 搜索过程概览

搜索采用分支定界法。若存在合法组曲且运行进入预热阶段，引擎会先精算一个方案作为**当前最好方案**，再把其他合法分配逐步划成更小的范围；若完整可行性检查穷尽后仍无分配，则可以直接证明不存在合法组曲。对每个仍需搜索的范围，引擎计算一个乐观分数，并严格保证它不会低于该范围内真实可完成方案的最高分。

例如，当前最好分是 9,100,000，而某个范围经过证明的上界只有 9,099,999，那么整个范围都可以删除。如果上界恰好也是 9,100,000，则仍要继续搜索，因为其中可能存在同分规则下更优先的稳定代表。无法计算或数值安全性不足的上界同样不能用于剪枝。

单队上界会估计一支未完成队伍最多能有多强，并暂时忽略一部分三队之间的竞争。三队联合上界还会同时把剩余角色组分配给三支队伍，因此不会乐观地让同一张物理卡同时帮助多队。由于两种放宽在其他方面并不相同，不能断言联合上界在每个节点都更小；实现会把它们与继承下来的整体上界取最小值。剩余组合足够小时，引擎停止估计，直接完整枚举这一小块。启发式只决定先搜索哪个分支，并帮助更早提高当前最好分；它不会删除候选。

下文依次定义搜索空间、推导两类上界、说明小块精确枚举，最后把这些事实组合成完整正确性证明。

## 1. 问题定义

设 `C` 为规范化后所有未排除的物理卡牌实例，并按角色分组；`Q` 为输入适配器生成的有限合法已拥有道具配置集合。歌曲位置 `s in {0,1,2}` 对应一支五卡队伍，且五卡之一是队长。

合法组曲 `(q, T0, T1, T2)` 必须同时满足：

1. `q` 属于 `Q`，并由三队共用；
2. 每支 `Ts` 恰有五张卡，角色 ID 两两不同；
3. 同一个物理卡牌实例不能出现在两支队伍中；
4. 每首歌保留输入位置，允许歌曲重复，不允许换序。

将 `hhwx-medley-bestdori-v3` 按固定运算顺序精确计算、结果取整数值的 binary64 分数记作 `score(q, Ts, s)`，目标为：

```text
S(q, T0, T1, T2) = (score(q, T0, 0) + score(q, T1, 1))
                    + score(q, T2, 2)
```

正式结果是使 `S` 最大的合法组曲。对同一五卡集合和歌曲，多个队长取得同样最高歌曲分时，保留实例 ID 最小的队长；完整组曲总分再相同时，先比较区域道具 ID，再依次比较三支队伍最终规范化成员数组，以此保留稳定代表。诊断列表最多保存搜索过程中实际遇到的十个不同方案；它不是经过证明的全局 Top 10。

## 2. 叶节点的精确计分

上界永远不能直接成为结果分数。任何可能进入结果的完整候选都必须交给基础契约规定的正式计分器。

对一个无序五卡集合，计分器按实例 ID 递增顺序计算五种队长选择，同歌曲分时保留先遇到的队长。成员先按稠密实例 ID 排序，再把队长移到输出索引 2，其余成员保持相对顺序。谱面与 combo 工作每次输入只准备一次；恒定技能倍率按 combo 段合并，只有真正随音符变化的倍率才逐音符计算。这套合并计算已与独立的 120 顺序参考实现作代数等价核对。

每首歌单独结算：

```text
song(l) = floor((5 * (base + sixthWindowExtra[l])
                 + sum(firstFiveWindowExtras[all five members])) / 5)
```

分子用有符号 `i128` 精确累加，只转换一次 binary64，除以五并向下取整。三首已经取整的整数分再按上一节的固定顺序相加。固定容量缓存可以复用完整五卡计分；冲突或淘汰只会导致重新计算，不会改变候选集合。

## 3. 搜索状态与不变量

卡牌采用稠密实例 ID，角色分组顺序固定。每个搜索节点包含三份 `TeamFamily` 和一份可回退的共享搜索域。

一份队伍范围记录：

- 已经为该歌曲选定的物理卡；
- 已经要求该队必须包含、但尚未指定物理卡的角色组；
- 普通角色枚举下一次允许使用的组索引；
- 五张物理卡全部确定后得到的该曲精确分数。

普通角色严格按递增组索引选择；必选角色必须先兑现，且本身不推进普通前缀。推导一项新要求时，`can_include` 已经拒绝该队加入所有“尚未成为必选且早于 `next_group`”的角色，对应的实际归属掩码也不会再包含该队；只要仍有要求，后备分支也会先兑现一项，才允许前缀继续前进。因此按归纳法，每个尚未兑现的必选角色在该队内互不重复、不与已选角色重复，并满足 `group >= next_group`。单队上界即使不强制必选角色、而只在普通后缀上取最大，仍然是在包含每个真实完成的超集上求值。这个表示既让每个普通无序队伍只有一种顺序，又不会禁止另一队使用同角色的另一张物理卡。

对每张仍可用的物理卡，搜索域保存四个可能去向：歌曲 0、歌曲 1、歌曲 2、不使用。每次限制都与已有掩码求交，并写入撤销记录。`counts[g][s]` 始终等于角色组 `g` 中仍可用、且存储掩码仍包含歌曲 `s` 的物理卡数量。选进队伍的卡会从剩余域移除；选择“不使用”的卡也会移除。DFS 回退时同时恢复可用性、去向掩码和计数。完成数会把互异必选角色的物理卡选择数相乘，并用组合动态规划计算普通后缀；饱和计数最多只会阻止节点进入局部精确收尾，不会删除任何完成。

建立联合上界前必须满足以下不变量：

1. 已选物理卡只在一队中出现，并且不再进入剩余分配；
2. 每队“已选物理卡数 + 必选角色数”不超过五；
3. 同队的已选与必选角色互不重复，且每个尚未兑现的必选角色不早于普通前缀；
4. 若一张卡已经不能不用，且只剩一个可行队伍去向，就必须把物理卡落实到该队，并同时兑现它对应的必选角色；
5. 因而，联合模型不会一边把某物理卡当作已固定成员，一边又把同一角色当作尚未兑现的必选位置。

第 4 条必须根据“当前实际可行去向”判断，不能只看存储的原始掩码。队伍容量、角色唯一性和普通前缀位置都可能让某去向失效，而不直接改写卡牌掩码。因此实现会把每个“实际只剩唯一队伍且不能不用”的卡先写回可撤销搜索域，再落实进队伍，然后从节点开头重新计算；重复至不再出现新单例。落实时若发生容量或同角色冲突，该节点确实无合法完成。

这个闭包不改变合法完成集合。当前节点的每个合法完成都只能把上述单例交给唯一剩余队伍；把它落实只是在状态里记下必然事实。先落实一张卡只会保持或缩小其他卡的去向，不会创造不存在的完成，也不会删掉把该卡送往其他队伍的完成——因为那种完成原本就不存在。

## 4. 单队分数上界

### 4.1 理想乘积

固定一首歌和一种仍可达成的全队技能条件，定义：

- `P`：当前道具配置下，五张卡综合力向上舍入后的和；
- `K`：歌曲基础系数、五张卡前五窗平均贡献，以及恰好一名队长贡献之和。

在文档规定的最终舍入包络下，正式整歌曲分数不会超过非负理想乘积 `P*K`。负技能增分可替换为零，因为这只会抬高结果。每张卡在 120 种顺序中各有 24 次处于前五个位置中的每一位，因此它的平均贡献是前五窗贡献和除以五。

从整数计分器到这个乘积的联系如下。令 `R(n) = 2^52 / (2^52 - n)` 并向上计算；对非负 binary64 加法，它保守覆盖 `n` 步运算的舍入误差。若选择了 `m` 个区域道具，综合力模型从计分器已经舍入过的卡牌／活动和、区域道具乘积这些原子出发，再乘以 `R(12 + 16m)` 覆盖其余加法树。固定的 12 次来自卡牌综合力累计五次、活动综合力累计五次，以及最后合并两次。每件区域道具最多把十五个“卡牌参数分量乘以倍率”的结果加入该道具小计，再把小计加入区域道具总和，因此每件至多增加 16 次。由此得到的加法形式 `P` 不小于计分器实际使用的队伍综合力。

对单个音符，`R(3)` 覆盖正式顺序 `(综合力 * 谱面系数) * combo * 判定`。把其正式向下取整的 `u32` 基分记为 `B`，以 `fl` 表示代码采用的 binary64 运算顺序，令 `muMax >= mu` 覆盖该卡与技能窗所有可达的实际技能倍率。实现取 `delta = nextUp(fl(nextUp(muMax) - 1))`：第一次向上覆盖 `B*mu` 的乘法舍入，第二次向上覆盖从一相减的舍入，因此保证：

```text
floor(fl(B * mu)) - B <= B * delta
```

倍率不大于一时令 `delta = 0`，也只会放宽上界。把基础分与技能窗增分相加，再应用精确的顺序频率 `24/120 = 1/5`，所得 `P*K` 覆盖 120 种顺序未取整均值。若计算出的乘积上界为 `U`，正式计分器的有符号 `i128` 均值分子为 `N`，则 `N <= 5*ceil(U)`。整数转 binary64 以及除以正数五都是单调运算，因此 `reference_ceiling(ceil(U))` 也覆盖最终转换和向下取整。以下不等式均以 `P >= 0`、`K >= 0`、`t > 0` 为前提。

对任意 `t > 0`，算术—几何平均不等式给出：

```text
4 * P * K <= (t * P + K / t)^2
```

固定 `t` 后，区分普通成员与队长身份，平方内的表达式就是各卡贡献之和。小型动态规划可以在保留已选成员、五个不同角色且恰有一名队长的条件下求它的最大值。实现取综合力／技能系数平衡点附近的三个正比例；每一个单独都是安全上界，所以取三者完整上界的最小值仍然安全。

全队技能条件不是猜测出来的。上界枚举所有仍可达成的混合、同团、同属性、同团同属性条件，再取最大。某一条件可以对不同剩余卡分别作有利放宽，使数值变得无法同时实现，但不会变得过低。五张卡全部确定后，直接使用真实全队条件向上计算 `P*K`，不再用加权最大化。

### 4.2 可回退的完整排序

每套道具配置都按角色、技能条件、歌曲、比例和普通／队长身份准备完整排序。列表包含全部合格卡牌，只让表头跳过已经从全局可用性中移除的卡；DFS 回退时用撤销记录恢复表头。这里有意忽略各队去向掩码和必选预留，所以是在超集上求最大。因此排序是为了避免重复扫描卡池，不是候选截断。上界顺便提出的完整队伍只用于安排搜索顺序，必须经过正式计分才可能成为当前最好方案。

若构造、范围检查或定向浮点运算无法证明有限上界，单队上界就是正无穷。“无法计算上界”只表示不能剪枝，不表示无解。

## 5. 三队联合分配上界

单队上界没有体现三队争用同一物理卡。联合放宽会同时给三个队伍分配所有剩余角色组。

### 5.1 把剩余乘积线性化

联合上界沿用单队上界的非负放宽模型：每张卡的综合力原子是上界；普通／队长技能系数则取该卡在所有仍可达成的全队条件中的最大贡献。不同卡可能分别取到无法同时成立的全队条件最大值，这只会扩大模型空间。每个真实完成都能映射到模型中相同的卡牌与身份，并且模型的 `P*K` 不小于它未结算的理想均值；结算与组曲级舍入在下文另行覆盖。

对一支模型队伍，把已固定与剩余部分拆开。`P0`、`K0` 是节点已固定的综合力与系数项的向上表示；`Pr`、`Kr` 是剩余分配决定的模型项，且 `Kr` 包含恰好一份队长贡献——队长可以已经固定，也可以仍在剩余卡中：

```text
P = P0 + Pr
K = K0 + Kr
P*K = P0*K0 + P0*Kr + K0*Pr + Pr*Kr
```

这是放宽模型中的代数拆分，不表示四个量等于正式计分器里的精确原量。第一项是常数，中间两项对剩余卡选择是线性的，只有 `Pr*Kr` 是非线性的。任选 `t > 0`，定义：

```text
A = t*Pr + Kr/t
```

于是 `Pr*Kr <= A^2/4`。如果定向计算可以保证每个放宽后合法完成都满足 `L <= A <= M`，由于 `x^2` 是凸函数，它在区间内不会超过连接 `(L,L^2)` 与 `(M,M^2)` 的弦线：

```text
A^2 <= (L + M)*A - L*M
Pr*Kr <= ((L + M)/4)*A - L*M/4
```

右侧已经变成剩余普通／队长卡权重的线性和。每张模型卡的上端点原子为 `add_up(mul_up(t,p), div_up(c,t))`，下端点原子使用对应的三次向下运算。`M` 是在“角色不同且恰有一名队长”的选择空间里，以向上加法求出的最大支撑值；`Lchoice` 是以向下加法求出的最小支撑值；最终 `L = max(Lchoice, mul_down(t,minResidualParameter))`。后两项都不大于任何允许的模型 `A`，所以取最大仍是下端点。忽略必选角色条件会扩大端点的共同选择域：最大值不会降低、最小值不会升高，所以 `M` 仍是上端点，`Lchoice` 仍是下端点；上一节的前缀不变量同时保证每个真实完成仍在该域中。

斜率 `s = (L+M)/4` 向上舍入；只在联合最大化结束后扣除的偏移 `o = L*M/4` 向下舍入。每张卡得到 `add_up(linearUpper, mul_up(s,upperEndpointAtom))`；三队偏移先向下合并，再由 `sub_up` 从向上的分配最大值中扣除。因此最终权重覆盖目标模型表达式。实现尝试三种 `t`，按完整单队上界而不是只按 `M` 选择最紧者。剩余综合力或技能系数为零，以及只差一张卡时，分别改用直接线性上界或完整乘积上界。

若某队已经有精确歌曲分数，就把它的非负部分直接加入常数。用零替换负的已结算分数同样只会放宽。其余模型项覆盖未取整的歌曲均值。每条非负歌曲贡献路径最多有四个 binary64 舍入点：把 `i128` 分子转换为 binary64、除以五，以及按固定顺序进行的两次组曲加法。中间的 `floor` 由单调性覆盖，不另算一个舍入点。因此，正式组曲分数不会超过“非负联合理想和上界向上乘以 `R(4)`”。这就是常数与偏移处理完后采用的最终联合分数包络。

### 5.2 角色内部选择

对每个角色组，每支队伍有三种身份：不出现、普通成员、队长；三队合计 `3^3 = 27` 种身份模式。每种模式都在角色组内精确匹配不同物理卡，遵守卡牌去向，并包含所有已经不能“不使用”的物理卡。

角色内部匹配只需保留每个“队伍 × 身份”中可到达候选的前四张。考虑某个位置采用一张排在前四名之后的卡：另外两支队伍最多占用前四名中的两张，某次条件查询最多再使其中一张不能用于这个位置，因此前四名中至少还剩一张可用，且权重不低于原卡；替换后不会降低角色内部最大值。条件查询会单独处理它指定的卡：查询某支队伍时把卡固定到该队，查询“不使用”时则从所有队伍身份中排除该卡。所有已经不能“不使用”的卡若不在前四名中也会加入，并作为完整必选集合检查。这是角色内部的替换论证，不是对完整卡池的截断。

### 5.3 数量状态动态规划

联合程序按角色组顺序扫描。每支队伍的状态分别记录已经消耗多少个“非必选”的剩余位置，以及是否已经提供队长。必选角色会在程序开始前预占队伍位置；实际选择它时不再重复消耗非必选位置。三队状态的笛卡尔积最多为 `10^3 = 1,000`，随队伍逐渐填满通常会继续缩小。

对角色 `g`，凡是局部身份模式的占位数与队长变化符合三队数量轴，就存在状态转移 `x -> y`。若模式 `r` 的向上舍入局部权重为 `w(g,r)`，前向递推为：

```text
F[g+1,y] = max(F[g,x] + w(g,r))
             对所有有效转移 (x,r) -> y 取最大
```

终点状态要求每队的非必选位置全部用完，且各有一名队长。因此终点最大值覆盖放宽空间内的每个剩余三队分配，同时在每个角色组内禁止复用物理卡，并在每队中保持角色唯一。最后加入常数、扣除向下舍入的偏移，再应用最终向上舍入包络，即得整套组曲上界。

后向表用同样方式计算最佳后缀。把某个局部选择夹在前向前缀与后向后缀之间，无需重新运行整套程序就能同时得到：

- 每张物理卡分别去三队或不使用的条件上界；
- 每个角色在三队中八种“剩余占位”掩码的条件上界；已固定成员及已经填满的队伍去向都不在剩余域中。

只有某去向／模式的条件上界严格低于精确当前最高分，或条件完成根本不存在时，才会删除它。若所有仍能同分或涨分的角色占位模式都包含某队，就把该角色标为该队必选；若没有任何竞争模式包含某队，就删除该去向。一轮内的所有推论都来自包含当前范围的同一个父放宽，可以一起应用；等分始终保留。

只有固定成员与固定分数未变、必选掩码完全相同、且每张卡的去向只收缩时，才能增量更新联合模型。发生变化的角色选择必须重算；前向前缀或后向后缀也只有在边界表逐项相同时才能复用。边界表记录该分界处每个数量状态的最优值；逐项相同意味着对后续任意转移而言，复用结果与重新计算没有区别。否则实现会尝试重建模型。若新的证明上界不可用或装不进搜索预算，仍可对更小的后代空间沿用先前有效的祖先整体／去向上界；角色占位推论则只能在满足增量更新条件时使用，否则跳过这项优化。复用只改变工作量，不改变实际完成集合。

## 6. 小型剩余乘积的精确收尾

三支队伍的剩余行数合计不超过当前局部上限时，搜索会生成三个队伍范围内的每个完整队伍；该上限最高为 256，剩余内存预算不足时还会继续降低。更大的范围若总行数不超过 1,024、较小两表的行数乘积不超过 65,536，且临时存储装得进预算，也可以直接收尾。这些阈值只决定采用哪种精确方法，不会丢弃行。

每行先携带对应歌曲的安全上界；只有它参与了无卡牌冲突且仍可能达到当前最好分的三队组合时，才延后进行精确五卡计分。直接连接会扫描全部合格三元组。索引连接则临时建立“物理卡／必选卡 → 最大表行”的位图，枚举另两表的全部行对，再枚举最大表中所有兼容行。两者都会：

1. 拒绝三队复用物理卡；
2. 要求每张已经不能“不使用”的卡确实出现在三队之一；
3. 只用严格落后的上界停止，保留同分候选；
4. 按 `(song0 + song1) + song2` 计算最终总分。

排序和位图只改变枚举顺序。一个收尾块完成后，行、索引和位图立即释放。

## 7. 完整遍历过程

搜索依次执行：

1. 验证至少存在一种合法十五卡分配；
2. 准备谱面相关计分数据，并为每套区域道具计算安全根上界；
3. 精确计算有限个确定性建议，以及一轮换卡／替换邻居，以尽早得到当前最高分；启发式失败不能证明无解；
4. 按估计质量从高到低处理每套道具，只有根上界严格低于当前最高分时才跳过；
5. 每个 DFS 节点重复检查继承上界、刷新受影响的单队上界并精算已完整队伍；若节点没有先由局部精确收尾关闭，则必须在建立联合上界前完成实际去向单例闭包，之后才能计算或更新联合上界并应用已经证明的条件推论；
6. 剩余乘积足够小时精确收尾，否则把一张仍有争议的物理卡按所有可行去向分支，包括“不使用”；联合选择不可用时，回到完整的递增角色前缀划分；
7. 恢复搜索域，继续处理兄弟分支，直到所有分支与道具配置都被穷尽或安全剪枝。

显式栈避免调用栈深度随卡池增长。分支顺序优先联合最大方案和条件差距较大的卡，但不会删除任何可行子分支。周期性完整方案探测可以提高当前最高分，不能认证或删除范围。

## 8. 为什么 `exact` 结果是全局最优

### 8.1 完整候选只使用精确计分器

每个报告方案都由始终保持队伍与物理卡约束的枚举过程产生，再由正式计分器计算。区域道具配置是否合法，是输入适配器已经验证并提供给搜索器的前提。上界和启发式估分不能直接进入结果。

### 8.2 不启用剪枝时会覆盖每个合法组曲

输入适配器列出 `Q` 中每套合法道具。固定配置内，递增角色前缀恰好覆盖每个无序五角色队伍；卡牌归属分支按三个队伍与“不使用”划分该卡的所有剩余完成；必选角色兑现会枚举该角色的每张合格物理卡；局部收尾会枚举所有行及所有无冲突三元组。正式计分器会对到达的每个五卡集合计算全部队长，并保留其中分数最高的确定性代表。因此关闭剪枝后，每个合法五卡集合三元组，以及它在所有队长选择中能取得的最高分，都会被表示。

### 8.3 每个剪枝分数都是安全上界

第 4 节从正式计分器到乘积的推导说明 `reference_ceiling(ceil(P*K))` 是单队已结算分数上界，算术—几何平均不等式则安全覆盖其中的 `P*K`。联合上界通过定向向上表示保留放宽模型中的常数项和线性代数项，只把 `Pr*Kr` 替换为合法的区间弦线上界；最终 `R(4)` 覆盖歌曲结算与组曲加法。之后在包含所有真实剩余分配的放宽空间上取最大。前后表条件值会在相应的条件放宽空间上取最大；只有对应条件根本没有完成，或某局部模式的安全上界已经严格低于精确可行截止分时，才把它记为不可用。向上运算抬高正项，向下运算减小被扣除的偏移。无法建立有限证明数值时，单队上界变成正无穷或停用联合优化。因此任何上界都不会低于它所代表范围里的最佳精确完成。

### 8.4 结构推论保留仍有竞争力的完成

某个卡牌去向或角色占位模式只有在无完成，或其安全条件上界严格无法追平当前最好分时才被删除。必选角色共识记录所有竞争占位模式共有的事实；实际去向单例闭包记录每个完成共有的唯一去向。这些操作都不会删除可能同分或涨分的完成。

### 8.5 合并以上四项保证

以上四项形成一条完整因果链。每个合法组曲要么被精确枚举，要么只会在已证明其无法追平当时精确可行的当前最好分后被删除。当前最好分不会下降，等分范围也不会被删除，因此已删除范围既不可能包含更高的最终分，也不可能包含同分规则下更优先的代表。

`search_medley` 只有在 `run_search` 正常返回时才给出 `exact`：此时要么完整可行性搜索已经证明不存在合法分配，要么每套区域道具配置和每个 DFS 范围都已穷尽或被安全删除。任何受控提前退出都返回 `incomplete`。因此，`exact` 且有 `best` 表示其中包含全局最高分及规定的同分代表；`exact` 且 `best = null` 表示不存在合法组曲；`incomplete` 不作这两项保证。

## 9. 数值与失败安全

证明路径使用明确的 binary64 向上／向下运算。正的上界项、弦线斜率和最终误差包络向上；下端点与被减偏移向下。如果上界构造无法得到安全有限值，就停用对应优化或把该值视为未知，而不是拿它剪枝。可控的分配、计数或索引失败会返回 `incomplete`。有符号 `i128` 的精确分数累加依靠已验证 `u32` 输入导出的静态范围证明，而不是每次相加都做失败检查。如果某个精确行分数高于其声称的局部上界，搜索返回 `scorer_disagreement`，不能继续给出虚假的证明。

每次按分数截断都严格比较一个已经精确算出的可行截止分：通常是全局当前最高分；局部连接内也可能是该固定行对已经精算出的最好候选。等分必须保留，因为稳定同分代表仍可能改善。无法得到有限证明上界时，会改用正无穷或停用这项优化，因此穷举仍可能正常完成 `exact`。搜索期间，可检测的正式计分／输入算术错误、受控分配失败、超时、取消、计数溢出与内部不一致会保守返回 `incomplete`，并可附带诊断用 `bestSoFar` 和已发现方案。结果补算发生在搜索之后；如果补算分数不一致，WebAssembly 调用会直接返回错误，不会交付任何一种搜索结束状态，因而也不会交付不一致的 `exact` 结果。如果进程、Worker 或浏览器被直接终止，则无法承诺生成最终结果，但也绝不会被报告成 `exact`。不存在“差距足够小就成功”的状态。

停止检查位于节点、候选和逐角色表计算之间，不插入每一次标量计分操作，所以时限是协作式截止，而不是硬实时保证。

## 10. 资源模型

配置的搜索存储预算包括局部行与索引、计分缓存容量、共享数量状态布局、仍由 DFS 祖先持有的联合快照，以及保守工作区预留。`peakSearchStorageBytes` 是预算口径，不是进程 RSS。输入、来源模型、正式计分临时数据、单队排序和部分遍历数据不计入该值；原生基准会另外采样进程工作集。

联合快照只保留到最后一个可能复用它的后代结束，并随引用释放；共享数量布局只计一次；局部行和位图只活在一个收尾块中；计分缓存容量固定。穷尽正确性不依赖任何缓存项一直存在。

最坏复杂度仍为指数级。实现不声称任意卡池都有多项式时间，也不承诺固定的实际完成时间。

## 11. 验证要求

任何改变枚举、上界或结构推论的代码，都必须通过最小针对性测试及完整 Rust 测试。现有测试特别覆盖：

- 不同内存预算、不同配置下，小型完整搜索与独立完整穷举参考结果一致；其中包括留下一张合格卡不用、且不同队伍省略不同角色的六角色用例；
- 单队与联合上界覆盖每个合法小型完成和队长；
- 前后表整体、卡牌去向与角色占位条件值同穷举分配一致；
- 必选角色、物理卡冲突、完整队伍、负增分和稳定同分；
- 跨越多个位图字、且故意让上界与精确分排序不同的扫描／索引连接一致性；
- 根据实际去向产生的唯一物理卡会被落实并兑现角色要求；
- 正式计分器与独立 120 顺序实现一致；
- 停止控制对象会原样保留原因；搜索预算不足返回未完成；严格输入校验、补全分数不一致，以及完整的“投影单例 `joint_step -> Restart`”调用顺序都有专项测试。

Rust 搜索代码变更后，必须执行 `npm run build:medley-foundation:wasm` 重建已提交的浏览器产物；普通 Next.js 构建不会生成或执行它。仓库目前没有端到端检查绑定的自动命令，因此发布验收必须通过组队计算器页面运行一个保留用例，并记录这项手工结果。

可运行命令、浏览器产物要求，以及可选私有真实档案比较的独立来源规则，见[组曲测试与验证](medley-testing.zh-CN.md)。历史分数比较只能补充公开证明测试，不能替代极小完整穷举和上界覆盖检查。

## 12. 范围与非目标

本设计在规则与计分文档规定的条件下证明 Top-1。它不证明全局 Top 10，不模拟原生判定历史或生命状态，不选择歌曲顺序，也不优化活动Pt；不使用分数量化、近似删除候选、外部存储或服务端搜索。任何会减少工作的优化，都必须先说明它代表的完成集合，以及保持该集合的安全不等式或精确划分，性能结果才可以视为安全。
