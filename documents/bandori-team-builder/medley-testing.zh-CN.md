# 组曲回归测试

英文版：[medley-testing.md](medley-testing.md)

## 用途与边界

私有样本库用于把独立组曲计算器与过去保存的真实 HHWX 输入和分数对照。它是防止搜索回归的证据，不是架构依据：测试脚本不会运行旧求解器、复算旧获胜队伍，也不会把历史结果作为新搜索的种子。

档案、来源容器、缓存主数据与谱面、历史报告、生成输入、输出和索引全部保存在 Git 忽略的 `temp/medley-regression-fixtures/`。其中可能包含私人账号数据，不得提交或公开。Git 只保存整理／比较工具和本文这份稳定测试流程；单次运行报告与私有资料一起保存。

保留样本包括早期 119 卡档案，以及卡数从 961 到 1,889 的 20 份完整卡池。即使 119 卡也不视作可以轻易穷举的微型输入。

## 证据模型

本地 `manifest.json` 是索引，记录文件校验值、档案内容校验值、日期别名、数据快照、历史报告位置、保存的设置和分数，以及是否留存队伍、区域道具与明确队长。账号身份和显示卡数只是标签，不能证明两份档案内容相同。

每个来源／档案／歌曲／设置组合会保留最高的主要报告分数及最完整的可用支持对象；字节完全相同的证据只保存一次。核验会检查归档哈希、档案解码和索引引用。

历史证据有明确局限：

- 旧报告通常没有保存准确源码提交和当次数据哈希；
- 早期 119 卡报告没有保存可配置的 PERFECT 率；
- 同一账号后来的档案若内容哈希不同，就是不同输入；
- 活动参数、歌曲、顺序、难度、PERFECT 率或数据不同的报告，不能作为同输入比较；
- `main`、`dev` 等目录名只说明证据在哪里找到，不一定是生成报告时的源码提交。

新测试会记录自己的源码提交与未提交差异、运行环境、限制、档案与规范化输入哈希、实际读取文件的哈希、完整输出、耗时、采样工作集和预算内搜索存储。这样可以让新运行本身可追溯，而不会把旧资料没有保存的事实擅自补成“已确认”。

## 整理与核验

以现有私有整理包为种子，并分别列出每个历史报告目录：

```sh
node --import tsx scripts/archive-bandori-medley-fixtures.mjs --seed <私有档案包> --source main=<报告目录> --source dev=<报告目录>
node --import tsx scripts/archive-bandori-medley-fixtures.mjs --verify
```

整理会保留已有原文件，只读取已知的 HHWX 报告格式；不收集二进制、日志或求解器源码。重复运行会更新索引，不删除过去已保留的证据。

## 比较契约

只有归档档案及旧报告明确记录的全部设置一致时，才纳入历史比较：歌曲 ID 与顺序、难度、PERFECT 率和活动设置都必须相同。旧报告通常没有保存每次运行的数据哈希和源码提交，因此事后无法证明当时的主数据快照也逐字节相同。这类参考是在“保留的 `main` 快照代表旧报告当时数据”这一明确假设下采用的回归目标；它本身既不能证明该分数在当前输入下可行，也不能证明新旧程序读取了完全相同的源数据。新搜索本身始终使用归档档案与保留的原始数据重新生成规范化输入。

验收分为两个独立门槛：

1. **分数回归：**有与全部已记录输入一致的参考时，新结果不得低于历史主要平均分；
2. **证明完成：**新结果必须是 `exact`。达到参考分后超时仍然不算精确性通过。

分数更高本身不能证明计分正确，因为多算也会导致更高。计分正确性由[基础说明](medley-foundation.zh-CN.md)中的 Bestdori／参考实现专项测试负责；真实档案验收主要检查在上述快照假设下的回归目标，以及搜索能否完成证明。

历史 `score`、`averageScore` 和完成标记必须保留原字段含义。报告附带候选不能代替主要结果。十五卡投影与它的完整来源卡池也是两个不同的搜索输入。

## 测试入口

完整 80 场验收命令为：

```sh
node --import tsx scripts/compare-bandori-medley-search.mjs --all-profiles
```

下列 20 份完整档案各跑无活动、活动 244、活动 260、活动 323 四种设置：

```text
961, 962, 972, 1036, 1039, 1051, 1127, 1161, 1211, 1229,
1252, 1318, 1329, 1425, 1433, 1513, 1522, 1703, 1747, 1889
```

全部采用 expert 歌曲 `385 -> 193 -> 619`、全 PERFECT、无 fever 和生成的全部已拥有区域道具配置；保留的全道具输入共有 108 套配置。各场顺序执行，每场限时 300 秒、搜索存储预算 256 MiB、采样原生进程停止线 1 GiB、外部截止 315 秒。Windows 每秒采样一次工作集，所以可能漏掉退出前不足一秒的短暂峰值；这既不是操作系统分配硬上限，也不是浏览器／WASM 增量内存。

即使某场失败，脚本也会继续完成其余场景，使最终资料完整；只要任何已选场景失败，进程最终返回非零。仍可使用下列较小范围：

```sh
node --import tsx scripts/compare-bandori-medley-search.mjs --case 119-no-event
node --import tsx scripts/compare-bandori-medley-search.mjs --remaining
node --import tsx scripts/compare-bandori-medley-search.mjs --completed-profiles
node --import tsx scripts/compare-bandori-medley-search.mjs --high-pressure
```

`--diagnose` 会开启限时剖析及脚本列出的阈值覆盖项。这些参数只用于 A/B 测量；普通验收模式会拒绝它们，也不会改动生产常量。

## 运行产物

每次运行都会在 `temp/medley-regression-fixtures/runs/<时间>/` 下写入 `run.json`、`summary.json`，以及逐场输入、输出和结果。需要保留的人工表格与说明也放在同一被忽略的运行目录。它们是绑定私有输入、特定源码提交和特定机器的测量结果，不是稳定的项目文档。
