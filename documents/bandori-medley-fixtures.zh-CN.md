# 本地组曲回归资料

英文版本：[bandori-medley-fixtures.md](bandori-medley-fixtures.md)

## 用途与边界

保留 main/dev 的历史结果，用来核对独立新计算器，不引入旧搜索架构。资料包括原始 HHWX 档案、缓存的主数据／谱面／活动数据、选出的原始报告和索引。整理脚本不运行旧求解器，也不启动新搜索。

真实档案、原始档案集合、报告、本机路径和生成的索引全部放在已被 Git 忽略的 `temp/medley-regression-fixtures/`，不得提交或公开。Git 只保存说明和测试工具；不增加依赖，不改应用代码。

首次收集包含 21 份不同的国服档案：119／1329／1889 卡的早期档案，以及两批各十份、其中两份重复的真实样本。这些都是完整卡池，119 张卡也不属于可以轻易穷举的极小输入。

## 整理与核验

用现成的私有档案整理包作为 `--seed`，分别传入保存历史报告的目录：

```sh
node --import tsx scripts/archive-bandori-medley-fixtures.mjs --seed <私有档案包> --source main=<报告目录> --source dev=<报告目录>
node --import tsx scripts/archive-bandori-medley-fixtures.mjs --verify
```

档案包采用现有的 `manifest.json` 格式，含档案、原始集合、数据和 `reference-only/` 报告。脚本保留其原文件，再读取已知的组曲基准、活动矩阵、独立进程测试和 low-memory HHWX 报告。不收集日志、二进制、转换成 Calc 格式的输入或求解器代码。再次传入相同来源可更新索引，已经复制的证据文件不会被删除。

本地 `README.md` 列出档案；`manifest.json` 记录：

- 档案内容校验值和带日期的别名；利用原始档案集合匹配报告中的匿名标识，不凭重复使用的 `P01–P10` 猜测对应关系；
- 各来源目录的数据快照，相同文件只保存一份；
- 原报告路径、日期、输入设置、分数，以及结果在报告中的位置；
- 是否保存了卡牌、道具 ID 和明确的队长；
- 哪些来源缺少缓存、哪些匿名结果未找到对应原档案。

每个来源／档案／歌曲／设置组合分别保留：最高报告分数、带卡牌和道具的最高分数、另有明确队长的最高分数。原整理包中的参考报告也保留；同一个文件被多项选中时不重复复制。核验覆盖文件校验值、实际 HHWX 档案解码和索引引用。

## 分数比较规则

1. 日常回归直接运行新搜索，与留存的历史平均总分比较，保持档案、歌曲顺序、难度、PERFECT 比例、活动设置及数据一致。不把运行旧求解器、复算旧队伍或向搜索提供旧答案作为前置步骤。旧队伍复算只留给之后确有需要的专项差异排查。
2. 对相同的完整输入，新搜索完成最优证明后的结果不得低于历史平均总分。未完成的结果即使暂时分数更高，也不算通过。单纯更高不能证明计分正确，因为多算分也会更高。
3. 原样保留 `score`、`averageScore` 以及旧报告的精确／完成标记，不擅自混同分数字段或把旧标记当成新证明。报告附带的候选队伍不一定就是报告中的第一名。
4. 数据快照只表示来源目录里实际保存的文件。缺少每次运行的数据校验值或提交号时，不能声称已确认那次运行用的版本；目录标签也不等于生成报告时的分支名。
5. 真实样本测试脚本固定 expert、全 PERFECT、无 fever；早期通用基准报告没有记录可配置的 PERFECT 比例，索引保留未知。比较时如作假设，应明确记录，不能悄悄补成历史事实。旧队伍缺队长时，不从卡牌顺序猜，也不因此阻止直接比较总分。
6. 从档案取十五张卡的小样本与原始完整卡池是两种搜索输入，不能直接比较两者的最优分数。

## 首批直接比较

运行 `node --import tsx scripts/compare-bandori-medley-search.mjs`，使用本地资料包。脚本构建原生 release 测试入口，输入完整 119 卡档案、expert 歌曲 `295 → 300 → 703`、全 PERFECT、无 fever，由搜索选择两套已拥有的合法道具配置。无活动的历史平均总分为 1,693,959，活动 323 为 1,781,877。这两份报告缺少历史 PERFECT 比例和当次数据校验值；本次明确记录采用全 PERFECT 和 main 目录留存缓存，不声称这些历史缺项已被证实。

每例限时 300 秒，候选存储预算 256 MiB。Windows 下每秒采样原生进程峰值工作集，达到 1 GiB 时停止；这不是操作系统硬性内存配额，也不是浏览器／WASM 内存。外部截止时间额外留 15 秒让正常超时结果返回。逐例执行，首个未完成或分数回退就停止，不自动增加预算或改算法。

输入、校验值、代码提交、历史设置、分数及差值、原生返回结果、计数、耗时和内存采样均保存在私有资料目录的 `runs/` 下，不复算旧队伍。不改变[基础计分规则](bandori-medley-foundation.zh-CN.md)；扩大卡池验收和修改算法仍须另外决定。
