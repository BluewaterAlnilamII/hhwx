# 个人主页整体设计与工作清单

English: [public-profile-design-plan.md](public-profile-design-plan.md).

更新于 2026-11-18。整体设计稿已完成；用户随后授权正式接入，并要求统一补齐动效和绑定账号开关联动。11 月 18 日的 Bandori 收藏接入结果见下方「Bandori 收藏」。正式接入工作与可选的字符计数规则调整不属于未完成的设计。

## 当前设计与已确认要求

以下以用户最新要求为准，移除被替代的视角切换、手机资料折叠、UID 复制和重复编辑入口。手机姓名位置采用用户提出的试排，经本轮授权的自主 critique/polish 比较后保留；这是本轮设计结论，不冒称用户曾逐项确认最终效果。

### 整体与导航

- 桌面左宽右窄，内容区沿用[分数追踪页宽度标准](theme-guide.zh-CN.md#默认内容宽度)，右侧个人资料 256px。右栏内 UID、日期与绑定账号自然连续排列，均左对齐，不重复分卡或标题。
- 左栏顶部使用小尺寸、左对齐的「主页 / 资料 / 设置」标签。切换只改变其下的内容，保留封面、身份区与右栏；设置仅本人可见。
- 主页收藏默认公开并按类别展示，取消收藏即移除。公开范围由设置控制，不增加“指定展示来源”、二次发布或另一套显示开关。
- 无公开收藏的访客看不到空栏目、空状态说明或隐藏数量；保留身份与已公开资料。

### 头部与直接编辑

- 桌面保留认可的构图：宽幅卡面、头像跨越边界、用户名与展示称号同排、签名在下；头图延续至半透明渐变身份区。上段图片约 6.4:1。
- 手机采用约 4.4:1 的短横幅和连续不透明身份底色。头像右侧显示称号，完整用户名从头像下方左侧开始，随后为签名、UID/加入日期、绑定账号 ID。没有实线分隔或资料折叠；深色主题使用对应的不透明底色。
- 用户名优先完整显示，可自然换行。布局检查包括总长 24 个英文/空格、连续英文及 24 个宽字母 W；不改变现行字符规则。用户名只展示，沿用既有专门编辑入口。
- UID 使用既有图标，取消复制功能。手机 UID 与“XX 加入”常驻同一行，桌面采用同样日期措辞。绑定账号也常驻显示。
- 本人可以点击头像直接选择。绑定游戏账号后，本人可以点击头部称号直接选择；尚未绑定时，桌面和手机都只展示当前默认称号。资料页展示各游戏账号已拥有的称号。
- 签名默认最多一行；本人点击后在原位置输入，失焦保存、Escape 撤销，无提交按钮。显示与输入均为 24px 高，长文本在输入区内部滚动。本人可编辑时，悬停头像或展示称号只压暗图像并居中显示铅笔；悬停签名提亮底色并显示文本光标。访客只看静态图文，签名不可展开，空签名不占行。
- 编辑焦点通过内部底色、光标及必要的键盘提示表达，不用外扩焦点框撑大布局。签名、UID/日期与绑定账号行采用统一 24px 内容高度、8px 行间距；用户名保留独立字号及换行空间。
- 封面右上角轻量按钮先打开「选择卡面 / 调整位置」菜单。头像与封面共用现有 BandoriCardPicker，保留搜索、筛选、排序和特训前后选择。
- 封面共用展示焦点，直接拖动实际图片调整，保存或取消；仅在可见图片正中显示无模糊底的准星，不添加说明、滑块或失真的双端预览。
- 移除整个“视角”功能和统管资料的「编辑资料」按钮。本人/访客仍按实际访问身份应用编辑与隐私规则。可见按钮、点击范围和悬停反馈一致，不让空白区域触发邻近操作。

### 资料与设置

- 只有资料标签页同时展示游戏 ID 和游戏用户名，使用 16px/600 的分组标题层级；以 10 个全角字符检查完整显示，不把该样例当成已经核实的游戏输入上限。
- **游戏用户名缺失时只显示 ID。** undefined、null、空字符串和纯空格都不创建名称节点，不显示“未知/未同步”等占位或残留空位，也不影响该账号称号。之后有名字时再跟在 ID 后。设置、桌面右栏和手机顶部始终只显示 ID 与区服图标。
- 资料页目前只展示账号已拥有称号，不展示账号卡牌。称号保持紧凑尺寸，按游戏分类及固有顺序连续排列；空组不占位，组间留一行，不增加分类标签、排序控件或重复分组标题。
- 设置分为「主页展示」和「绑定账号」，可用内容宽度足够时双列，低于 600px 时单列；不按整个窗口宽度误判列数。
- 模块类型固定，在设置短列表中调整顺序与公开状态；拖动、键盘和触摸排序立即生效，没有主页一级排序按钮或额外保存步骤。模块顺序与收藏项内部顺序不同。
- 绑定账号隐私为总开关 → 账号开关及账号排序 → 每个账号的称号开关。总开关和账号开关统一控制资料页、桌面右栏及手机顶部，顺序也同步应用。
- 父级关闭时保留下级选择并禁用子开关，重新开启后恢复。只隐藏称号时保留公开账号身份。预留数据层级，但不显示尚不存在的数据开关。
- 本人保留私密模块/账号/称号，以眼睛划线图标标示，不显示“仅自己可见”文字；访客完全不看到这些内容或其数量。

### 2026-11-18 保存与加载规则复核

- 「已保存」确认刚刚操作的栏目。两个标签页操作同一栏时，以最后成功保存的那一版为准。例如第二页保存绑定账号时显示 A 公开、B 隐藏，最终就是 A 公开、B 隐藏。同一栏内保留被上级开关暂时禁用的下级选择。
- 收藏模块和绑定账号是两个独立栏目。第一页保存收藏顺序，第二页保存绑定账号，两次结果都应保留。签名也是独立操作，失焦保存与此次点击的开关应各自完成，成功或失败各自在原位置反馈。
- 资料标签内容作为一个模块处理必需数据的加载失败，整个模块共用一个失败和重试入口。若本次只展示公开账号身份，称号目录不属于这个模块的必需数据。
- [x] 修正签名保存占用隐私开关的问题。保存签名只更新签名，设置里的实际绑定账号继续显示。
- [x] 自动档案用 `UID <该账号的游戏 ID>` 代替缺失游戏名时，资料页只显示一次游戏 ID。
- [x] 两个设置栏目各自保存整栏选择。Chrome 双标签页验证了同栏最后保存的选择生效，另一栏的修改在刷新后保留；在同一页延迟任一栏并让它保存失败，另一栏仍可保存。
- [x] 未绑定账号时，头部默认称号以静态图片展示。已在 390px 和 1440px 核对悬停和点击，头像仍可编辑。
- [x] 顶部继续读取共用称号目录。模拟目录不可用时，仅展示账号身份的资料页正常显示；展示称号列表的资料页提供一处模块级重试，恢复后顶部和资料列表均显示称号。

## 参考如何影响设计

| 参考 | 采用的经验 | 对应结果 |
| --- | --- | --- |
| 用户提供的 Bilibili 截图 | 宽幅封面、封面右侧轻量编辑、主栏分区 | 操作就近，封面菜单紧凑；视角按后续要求移除 |
| 用户提供的知乎截图 | 跨封面头像、身份层级、左栏局部导航 | 桌面与手机分别组织身份内容，三个标签共享框架 |
| [Steam 展示柜](https://steamcommunity.com/tradingcards/faq/) | 标准类型模块的个性化配置 | 设置内顺序与公开状态，模块内部以后细化 |
| [GitHub 置顶内容](https://docs.github.com/en/account-and-profile/how-tos/profile-customization/pinning-items-to-your-profile) | 固定项目及排序的交互参考 | 仅作为未来收藏模块内部参考，不改变自动展示规则 |
| HHWX 当前主题及组件 | 58px 工具栏、270px 桌面站点导航、语义色、UID 图标和卡面选择器 | 延续既有产品风格与行为，不为检测器风格提示重做主题 |

Bilibili/知乎分析基于用户截图；Steam/GitHub为官方资料，不声称操作过其登录态编辑器。旧工作区实现不是当前检出代码已经具备的功能。

### Bandori 收藏

各收藏标题用括号显示该类收藏总数。活动按所有区服的收藏场次合计。横幅图片和活动名称都可打开详情。桌面端两者之间的窄缝也属于该链接。活动名称下方依次显示主题乐队图标、加成属性图标和状态文字，三者同排。混合乐队活动只展示属性图标和状态。当前区服还有后续收藏活动未显示时，预览时间线从最后一个节点延伸出一段虚线。「全部」页的横向时间线换行时，实线延伸到当前行的右边缘。整条时间线在最后一个活动节点收尾。

在自己的主页，鼠标从横幅移到活动名称时，右上角的取消收藏星标持续显示。用键盘聚焦活动链接也会显示星标。触屏上，第一次点横幅显示星标，再点同一横幅进入详情。点名称始终直接进入详情。星标只取消当前区服的这一场活动。访客点横幅可直接进入详情。

本人可从「收藏的活动」标题栏右侧的铅笔进入编辑页，用国旗切换区服。列表沿用该服完整时间线的顺序。桌面每行依次显示主题乐队与加成属性图标、期数、短横线、活动名称以及取消收藏的星标。手机第一行显示图标和期数，第二行显示名称，星标靠右。混合乐队活动只显示属性图标。点击名称进入该区服的活动详情。

「收藏的歌曲」按歌单展示。预览、展开和编辑时，栏目标题下方直接显示曲目。桌面每行在封面右侧上下排列歌名与乐队，另列专辑和时长。手机把时长放在乐队旁，行末常驻更多操作。Bandori 专辑名为 `BanG Dream In-Game Version`，OurNotes 曲目在播放器中使用 `Our Notes In-Game Version`。桌面双击歌曲行或单击序号处的播放按钮，手机轻点歌曲行，即可从该曲开始播放整张收藏歌单，包括主页预览以外的可播放曲目。封面和歌名沿用整行的悬浮效果。右键、触屏长按和「···」都可打开管理菜单。桌面滚动时菜单固定在屏幕上的原位，点击菜单外会收起菜单，并执行该处的操作。主要使用触屏的设备在竖屏和横屏下都从底部打开菜单，轻点遮罩只收起菜单。播放器中的封面和歌名可打开详情。更多操作支持「下一首播放」「加入播放队列」，本人还可取消收藏。

主页上的铅笔直接打开整张歌单并进入编辑模式。在歌单中点铅笔或对勾即可原位切换。序号换成拖动手柄，更多按钮换成取消收藏的星标。切换动效只作用于控件，并跟随系统的减少动态效果设置。编辑时整行仍可播放，歌曲管理菜单在浏览模式下可用。每次拖动放下后自动保存，主页预览取新顺序的前十首，再次开始的播放队列也按新顺序排列。新收藏的歌曲追加在末尾。

再次触发当前歌曲行会从头播放，并保留当前队列，包括手动加入的曲目。行首的播放／暂停按钮可暂停或从原进度继续。手机封面只显示图片，浏览时当前歌曲的序号位置显示播放／暂停按钮。

卡牌与活动的编辑列表使用相同的标题字重。桌面为角色或活动期数留出独立一列，手机把名称放在第二行。手机歌曲编辑列表中的收藏星标有 44 × 44 像素的触控区域。取消收藏后，栏目标题处显示「已保存」。键盘焦点移到下一项，删除末项时移到上一项，当前没有相邻条目时移到标题。

打开本人的完整歌单后，可以从封面、歌名、歌曲信息或行内空白处拖动排序。鼠标在浏览和编辑两种模式下都可以拖动，编辑模式下行内显示抓手光标。触屏编辑时可以直接拖手柄，也可以在行内稍作停留后拖动；快速上下滑动仍然滚动页面。触屏浏览时长按打开歌曲菜单。主页预览按保存的顺序展示并支持播放。

- 卡牌与歌曲默认按加入收藏的先后顺序展示，先收藏的排在前面。主页最多预览六张完整卡面和十首歌曲，卡面以大小错落的拼贴呈现。接近视口时，若卡面超过铺满格子所需实际像素宽高的 1.5 倍，浏览器先将卡面缩至 1.5 倍，其余卡面直接使用原图。最后由浏览器按格子尺寸显示和裁剪，全程不加锐化。有双卡面的卡牌默认展示特训后，本人可用右上角的双弧形箭头切换卡面并保留收藏顺序。本人可点击切换按钮左边的实心星取消收藏，按钮不显示人数。取消成功后立即移除卡面，后续收藏自动补位。触屏上第一次轻点卡面时才显示卡牌信息和操作按钮，再点卡面进入详情。
- 桌面端一、三、六张布局按国服 10.1.3 普通成员详情的无框插画取景比例 2001∶1325 确定基础格高度（1334 宽的原画缩至 0.36 倍，可见高度为 318）。两张布局按 3∶2 分宽。四张布局的上排同两张布局，下排反向按 2∶3 分宽，第 1、4 张为宽图。每排都由 4∶3 的窄图定高。五张布局的上排按 1.618∶1 分宽，由右侧 4∶3 的窄图定高；下排三格等宽，均为 4∶3。同一栏宽下，这些尾组的总高最多为六张满组的高度。
- 移动端每组六张按收藏顺序分四行展示，每行依次为 1、2、2、1 张，「全部」继续按此规律排列。并排的两张图各按原生取景 2001∶1325 展示。仅收藏一张时，这张图按原生比例通栏展示。有多张收藏时，通栏图统一按 2∶1 展示，包括末组单独剩下的一张。
- 本人可点卡牌标题旁的编辑按钮，在本栏编辑列表中拖动卡牌或图形分界线，每次放下自动保存。可从缩略图、名称或行内空白处起拖。手机长按行后拖动，直接滑动则滚动页面。手柄支持键盘排序。乐队图标排在角色名前。桌面一行并列显示角色名与卡名，手机分成两行，各自溢出时以省略号截断。分界线上方的 1 至 6 张用于首页预览，跨线拖入或拖出会增减展示数，满六张时拖入会挤出末位。新卡追加在末尾。默认跟随末尾展示前六张以内的卡牌。若线下还有卡，新收藏不改变首页展示数；拖动或取消收藏使所有剩余卡都在线上时，恢复跟随末尾。
- 在卡牌编辑列表中，点击缩略图、角色名或卡名均可进入卡牌详情。点击星标即可取消收藏。桌面端星标紧跟卡名，移动端星标位于每行最右侧。星标旁的斜向双箭头可切换特训前后卡面，列表头像和图片墙同步更新。无法切换时，两处都保留原位的灰色禁用按钮。卡牌编辑成功后统一提示「已保存」。
- 已收录的活动可以在任一区服提前收藏，各服分别计数。时间线默认选中收藏场次最多的区服，并列时按站内区服顺序。优先展示最近结束的一期和正在进行或未来的三期，一侧不足时从另一侧顺序补齐。打开主页或切回主页时，按当前时间重新计算活动状态和预览场次。活动状态沿用活动详情。本服尚无排期时显示「未开始」，日期栏显示「—」，按活动 ID 升序排在已排期活动之后，也占用后续活动的名额。有本服预计或官方排期后，同一条收藏按日期排列。

## 数据调查与正式接入边界

### 长度

src/lib/username-policy.ts 定义 2–24 个 Unicode 码点，使用 Array.from(value).length；先去两端空白并折叠连续空格。注册/资料前端与接口共用，基线迁移使用 char_length(username) BETWEEN 2 AND 24。没有查询线上数据库或确认存量实际最大值。A、中、😀均为 1；家庭组合 emoji 为 7，é 为 1，e 加组合重音为 2，不等于视觉字形数。

主页签名限 80 个半角单位。半角字母、内部空格和半角片假名各计 1，汉字、全角标点和 emoji 图形各计 2。按完整字形接收输入，粘贴到中间时保留光标后的文字，输入法在确认候选词时计数。保存接口去除两端空白后校验同一上限。完整设置请求另有 32 KiB 大小限制。

### 游戏用户名

snapshotToNormalizedProfile 从同步快照读取 profile.user_name，syncAutoGameProfile 通过 upsert_auto_game_profile 存入 profile_name。现有 GET /api/account/game-bind/bindings 只返回 game_uid/bound_at；有绑定不等于已同步档案。正式 GET /api/users/[publicUid] 从同一用户的 CN 自动档案读取可用名字，缺名或辅助名字查询失败时省略；不新增强制同步要求。设置、侧栏和手机摘要仅显示 ID。

### CN 称号分组

委派调查核实本地 CN 10.1.3、versionCode 106（留存日期 2026-11-02）的 ARM64 方法及界面 prefab。五类为普通、角色、活动点数排名、其他活动、特效；中文词条由 CN master 20260612160059 与 APK key 对应，不是当前在线词条快照。证据为原型目录 cn-degree-grouping-evidence.md。

先判断实际拥有特效变体/内置动画，再按角色关联与 degreeType 分组。前四组按 master.seq；特效组先排已拥有的特效变体，再接内置动画，各批内部按 seq。仅有可用特效资源不让普通变体进入特效组。现有 BandoriDegreeCatalogItem 与 ownedDegreeEffectIds 可推导分类，无需为分类新增 API 字段。未运行游戏或验证在线 IFix。原型每服六个静态样例来自真实目录字段和图片，拥有状态为示例；动态变体在正式集成时验证。
