## 回复与回应——已实现范围（2026-10-27）

初始范围为回应和引用一条原消息的回复，没有回复提醒开关。最初不做 @ 的限制由下方单独确认的 @ 阶段替代。一次多图/文字提交只在第一条消息保存引用。主动回复开启作者分组，普通续发继续简并；原消息缺失统一显示“消息已删除”。

复用评论区回应标签、表情网格和参与者组件，沿用 Radix 消息菜单、账号所属 ChatSession 发送队列及服务端 RPC 边界。留言板新增的行为为直接原消息预览、临时原消息上下文和仅完整消息频道发布的版本化回应事件。界面复核后去掉悬停工具栏、独立回应弹窗、回复标题及返回原位置按钮；已有回应时展示共享添加按钮，回应网格保留 256px 高度上限。留言板表情面板复用 Radix 已安装的 `react-remove-scroll` 2.7.2 锁住背景滚动，将其声明为直接依赖，未改变包版本。具体行为及上线顺序见[接入说明](realtime-message-board.zh-CN.md)，验收证据见[验证记录](realtime-message-board-validation.zh-CN.md)。没有新增通知集成或生产操作。

快捷回应默认依次为 `:Tae:`、`:KokoroYay:`、`:LisaMelt:`；主动选择并成功添加才更新最近三个表情，按账号保存于浏览器本地。点击已有标签追加、撤回和失败均不改变顺序。共享表情入口统一使用 Lucide `SmilePlus`。

## @ 提及——确认范围（2026-10-28）

实现严格限定 8 个结果的紧凑候选列表、主动选人后绑定账号的提及、不带数量的外侧单个气泡，以及面板内按从旧到新处理的提醒队列。点击定位，关闭仅处理当前一条且不移动阅读位置；前台实际看到的消息单独确认，包括不在提醒首个窗口中的较新消息。引用继续独立，没有 @ 开关或自动提醒；重复收件人、重试和多图提交不会重复产生提醒。复用既有用户行、消息时间、会话状态归属、认证 API/RPC 边界及同一 broker 连接。新增私有持久记录和账号专属失效频道，支持刷新、离线恢复和设备同步；普通未读游标保留原有语义。

没有待确认的产品选择。[已实现行为及上线顺序](realtime-message-board.zh-CN.md)和[验证记录](realtime-message-board-validation.zh-CN.md)分别维护。生产操作仍不在范围内。

## 轻量摘要、未读状态与原生恢复

每个已登录标签页持有一条留言板连接。面板关闭时保持 `chat_activity:main` 摘要订阅；只有打开面板时，才通过订阅令牌订阅完整消息频道 `chat:main`。个人通知保持原有实现，访客不建立这些订阅。

- 登录后先订阅摘要，再读取 `GET /api/chat/activity`。接口只返回 `{latest,latestOther}` 游标，不读取正文、作者资料或未读数量。新增事件携带游标与作者 ID，删除事件携带消息 ID。他人的文字和图片可点亮入口红点；自己的消息与贴纸不触发红点。
- 持久化已读位置使用 `(createdAt,id)`，按账号和房间保存在 `localStorage`。首次使用以当前最新位置初始化，不将旧历史全部标成未读。同一浏览器的其他标签页通过 storage 事件单调推进；不增加跨设备已读同步。只有面板可见、页面有焦点且最新底部已渲染，才推进已读位置。打开旧阅读位置不等于已读；不使用 broker offset 作为已读游标。
- 首次打开先订阅完整消息，再请求 `GET /api/chat/messages?activity=1`。服务端通过一个仅 service_role 可用的 `read_chat_snapshot` RPC，在同一数据库快照中返回最新 50 条和摘要，读取期间缓存实时事件。
- 有有效本地基线且 `recovered:true` 时直接应用 SDK 补发，**不请求历史**。关闭重开保留 Subscription 对象及恢复位置。新增与删除按 ID 幂等应用；瞬时贴纸发布使用 `skip_history:true`，不进入补发。
- 无法恢复或没有有效基线时，仅请求一次最新页，替换旧列表并回到最新位置。保留草稿、待上传内容、失败项及本地已读位置。不再核对保留 ID、拼接断开的旧历史或向后翻页补齐缺口。面板关闭时只恢复摘要，完整消息等打开后加载。
- 关闭保留已加载消息、分页位置和滚动锚点，释放已确认消息的媒体预览，并取消完整消息订阅。待发送附件和上传仍由账号持有。页面隐藏或失焦时暂停已读推进，不主动断开连接。Stamp 播放只要求留言板打开，不要求页面拥有焦点或处于可见状态。页面隐藏时不丢弃新效果，也不清除当前效果或声音；原有时限继续计时，不排队等待回到前台。关闭留言板仍会取消播放。浏览器自身的后台调度和音频策略仍然适用。退出或切换账号时销毁该账号的内存状态和连接。
- 重连期间仍可阅读缓存、跳到列表底部，HTTP 发送成功立即显示。历史读取失败只重试该读取，不拆掉正常的 WebSocket。健康连接不轮询。删除当前摘要所指的消息时合并触发一次摘要读取，普通新消息不查询。

两个频道都在 Centrifugo 内存中最多保留 **256 个事件、300 秒**，并强制启用恢复。条数或时间任一超限都会无法恢复，服务重启也会丢失缓存。这用于短暂断线，不提供持久投递保证。数据库已提交但发布失败的变更，要等之后重新取得快照才能看见；outbox 本次仍不实现。

上线顺序为先应用 `20261026072628_chat_activity_and_snapshot.sql`，再更新 broker 配置，最后部署应用。迁移只新增两个固定空 search_path、仅 service_role 可执行的 invoker RPC，不增加表或已读写入。新标签页通过 `POST /api/chat/connection?activity=1` 使用摘要模式；旧请求仍获得原有完整消息服务端订阅。原 before/after 历史接口保持兼容，新客户端不再依赖向后分页恢复。回滚可保留新增 RPC 和历史配置并恢复旧应用。本次只进行本地修改，不包含生产操作。

参考的是 Discord 将非当前会话的轻量活动与正在阅读的完整消息分离、能恢复则补发否则重新初始化的做法，不声称复刻其私有网页协议：[passive sessions](https://discord.com/blog/how-discord-reduced-websocket-traffic-by-40-percent)、[Gateway 恢复](https://docs.discord.com/developers/events/gateway#resuming)、[Centrifugo 恢复](https://centrifugal.dev/docs/server/history_and_recovery)。实现使用现有 Centrifuge SDK。

## 已确定的前端设计

- 顶部只保留标题和关闭按钮；输入区上方不显示通用错误条或手动重连按钮。已保存消息的发送失败由各自的重试图标处理，瞬时 stamp 失败不添加提示；限额和禁言反馈仅用于解释发送限制。
- 他人气泡在左侧，使用现有头像，用户名后跟评论区同款 UID 符号；自己的气泡在右侧，不显示头像、用户名或 UID。连续同作者消息合并展示身份。
- 开头、间隔五分钟或跨日期时显示居中共用时间。今天仅时间，昨天加“昨天”，更早消息带日期。
- 复制、图片另存为、允许的删除及管理操作使用现有右键/长按菜单，也支持 Shift+F10。复制保留 PNG 剪贴板表示，不修改源文件；另存为优先打开系统保存窗口，没有该接口的触屏设备使用系统文件分享，不支持时打开现有预览供原生图片操作，其他浏览器沿用普通下载，取消就结束。不转码，不添加保存中/成功/失败/重试界面。失败图片与当前消息窗口仍持有本地预览的已发送图片，显示/复制/保存均复用本地 Blob；其他已发送图片使用匿名 CORS 读取公开 CDN，确认成功不会立即重载图片。系统和浏览器决定相册操作。已发送和失败消息都显示“删除”：失败消息只删本地条目，已发送消息沿用确认与删除 API。输入区上方不添加操作提示行。菜单关闭、发送和删除不强制聚焦输入框；Enter 发送保留输入框已有焦点。
- 已发送及待发送/失败图片均可点开同一查看器。消息长按保留聊天菜单，大图允许浏览器原生图片菜单。点击图片和拖动结束保持打开，点击背景、关闭按钮或 Esc 才关闭；保留双指/滚轮缩放，复用本地 Blob，不增加业务请求。
- 仅在离开底部或还有较新消息未加载时出现悬浮向下箭头；阅读旧内容时保持滚动位置。
- 输入区使用一行布局：左侧加号，提示文字“输入消息...”，输入框末尾放表情和 stamp 控件，右侧发送。加号菜单提供图片选择及发送前预览。stamp 控件直接发送独立瞬时效果，完整链路见下文。
- 复用评论区表情选择、光标替换、短码保存及行内/大表情渲染。选表情只修改草稿，不立即发送；打开留言板预加载共享 stamp 目录，具体媒体按需读取。Stamp 是独立瞬时动画，不作为文字/历史消息。
- 多行输入增长到高度上限，保留中文输入、空白/计数、顺序请求、独立待发状态和重试逻辑。临近上限才显示字数。
- 适配桌面浮层、主题角色和可访问名称/焦点。手机端外层不透明背景覆盖完整布局区域，仅内部会话随键盘上方实际可视区域调整，避免露出后面的页面。本轮界面不增加数据库或认证查询，不需要数据库迁移。

## 文字和发送

1. 原始输入按 Unicode 码点计数，包含空白，最多 1,000 个。发送时 trim，纯空白不发送。中文输入法选字不触发发送；Enter 发送，Shift+Enter 换行。
2. 每次提交立即清空输入框，并追加一个有独立请求 UUID 的待发消息。后续可以继续输入和提交。
3. 客户端顺序发送 HTTP 请求；WebSocket 连接、重连、历史同步及上一条的等待均不锁输入框。
4. 每条消息分别显示排队、发送或失败。API fetch 超时为 30 秒、图片 PUT 为五分钟，超时释放队列并进入既有手动重试流程。失败内容保留在该消息，重试复用原请求 ID，不覆盖新的草稿。新的同文消息仍生成新 ID。
5. HTTP 保存结果和实时广播按 UUID 合并。即使实时通道暂不可用，HTTP 成功也显示已保存；同步中的旧历史不能覆盖新确认。
6. 已知限速、禁言、认证/网络失败时，不继续发明知无效的队列请求，剩余消息保留为可手动重试状态。不加入持久离线发件箱或无限自动重试。

## 限速和数据库

- 每账号从本轮首条成功保存开始计时 60 秒，最多 20 条；允许连续发言，多设备/标签页共用额度。采用固定轮次，接受窗口交界附近的短时突发。
- 重试不重复计数，保存失败不计数，删除不退额度；保存成功但广播失败仍计数。达到上限显示服务器返回的恢复时间，浏览器本地更新倒计时，不轮询。
- 通过 CLI 创建增量迁移 `20261023205032_chat_sending_and_query_cleanup.sql`，替换 `user_state.next_send_at` 为窗口开始时间和计数，保留消息/禁言；现有响应 `nextSendAt` 在额度耗尽时返回本轮截止时间，否则为 null。
- 一次 Auth `getUser` 验证身份后，只执行一次保存 RPC。事务读取/锁定该账号状态，检查幂等请求、禁言和限额，保存消息并更新一次计数。正常路径不再反复插入已存在的状态行。
- 不读 `account_status`，不统计历史消息计算额度，不定时清零，不单独查询限额。作者存在性及展示资料合并读取，连接信息一次读取用户状态，历史分页后关联作者资料。
- 两张私有表、服务端 invoker RPC、RLS/权限、请求 UUID 唯一约束及游标/保留期索引保持。浏览器没有直接表/RPC 授权。
- 删除和管理仍在数据库检查归属/角色；这些实际业务权限不因移除邮箱查询而省略。

## 实时同步与生命周期

以本文首节的账号连接、双频道、原生恢复和本地已读规则为准。保留 30 天，每十分钟最多清理 1,000 条过期记录；自然过期不逐条广播。不增加个人通知改造、outbox、跨设备已读、额外消息框架或后台轮询。

## 图片扩展（2026-10-24）

- 用户已授权本地实现：单图单消息、公开 CDN、浏览器 Presigned PUT 直传，前缀 `user/images/temporary/`。图片独立显示，无文字气泡内边距。
- 最终文件上限 20 MiB（界面标为 20 MB），总像素上限 16,777,216，单边上限 16,383。普通静态 JPEG/PNG/WebP 保留原文件；仅超限时在 Worker 中按比例缩小/编码，保留透明背景。GIF、动态 WebP、APNG 符合限制时原样上传，超限明确拒绝，首期不转码动画。
- 选图/粘贴累计最多十个文件，处理中也计入，超出时提示未添加的文件名。Worker 逐张处理，选择/处理/预览不访问服务端；每张预览右上角可移除。共用发送按钮提交图片及可选文字，只清空已接受的草稿；按预览顺序依次保存图片，最后保存同批文字，之后单独提交的文字仍可独立发送。
- 图片失败后，该条及同批尚未发送内容均保留，逐条显示红色感叹号重试，并支持菜单移除；重试只处理选中项，手动重试可能改变顺序。已上传时仅重试保存。不增加持久批次记录、接口或额外请求。退出账号清理资源，刷新不持久化未完成上传。
- 数据库仍只有原来两张表：消息增加图片路径、类型、宽高、字节数；状态增加上传窗口与计数。上传授权每账号 60 秒最多 20 次；文字及图片成功保存共用原有 20 条消息额度，不以历史 COUNT 限流。
- 普通成功路径为两次业务 RPC、一次 R2 PUT、一次 HEAD；身份验证另计。HEAD 检查实际字节数及保存的类型/缓存头，不解码像素。签名绑定长度、类型、缓存头及禁止覆盖条件。实际 R2 的长度拒绝与 CORS 仍需部署目标验证。
- 公开图片 URL 没有下载凭证有效期；缓存使用一年 immutable。源文件按前缀配置 31 天生命周期，不扫描桶、不逐条删除或清除缓存。上传链接有效 1 小时，发布凭证最长 23 小时，确认时检查对象年龄，避免新消息引用即将过期的旧文件。
- 复用现有图片查看器，放大上限允许达到图片原始分辨率；列表按比例完整显示、不放大小图、预留尺寸并懒加载。首期列表和查看器共用一个文件，因此小尺寸显示不会减少下载字节数。
- 实施参考：现有聊天身份/保存/删除及评论区作者展示，`ImageViewer`、`LoadingImage`；R2 写入使用服务端 AWS S3 SDK，不改游戏资源只读凭证。远端配置和部署未授权。

## Stamp 发送与播放（2026-10-24）

- 本轮范围：完整的 HTTP 鉴权、独立额度、Centrifugo 广播、客户端播放及固定 CDN 素材。本地验证须实际运行服务端并连接两个客户端；单独播放预览不能证明发送链路可用。
- 复用评论区目录、区服选择。留言板图片区域为手机端 120×80、桌面端 144×96；评论区继续使用 96×64 / 114×76。图片、名字底板、语音标识的完整组合随机放在消息可见区域内，不随消息滚动。尺寸观察器在区域改变时保持组合不越界，仅在整个区域放不下时缩小。
- 公开 UID 的余数 1/2/3/4/0 对应 P1/P2/P3/P4/P5。身份复用已经加载的账号资料，不为每个 stamp 查询。名字底板为 120×24 / 144×28，默认字号 11 / 11.5 px，不加粗。在显示前按实际可用宽度缩小过长用户名，最低 9 px；仍放不下时才省略。仅在尺寸或字体加载变化时重新测量，不逐动画帧计算。
- 名字和底板立即出现，图片或图集加载前图片区域自然留空。进入缩放 200 ms，采用游戏的二次缓出曲线；3000 ms 开始退出，3200 ms 移除。资源加载不重新计时。动态图片播放一轮，不修改评论区缓存中原有的循环设置。减少动态效果偏好下跳过缩放，沿用动画播放器的静态处理。
- 每个发送者最多一个、画面同时最多五个。新效果替换同一人的旧画面及音效；第六名发送者替换最早仍显示的一组。不排队、不另加接收速率限制。晚到的资源不能恢复已移除效果。
- 普通 stamp 播放 `SE_UI_STUMP`，语音及变体 stamp 播放自己的音效，不叠加公共声音。仅普通语音 stamp 显示语音标识。自然消失允许语音尾音继续；替换、挤出、关闭、页面隐藏及退出账号会取消相应声音。
- 复用 Web Audio 上下文；音频预加载只预热浏览器 HTTP 缓存，播放时才解码，不保留已完成的缓冲区。打开留言板预加载三份通用素材；悬停/键盘聚焦只预热该 stamp 的语音，动画沿用选择器已有预热。浏览器不允许播放声音时画面仍可用。评论区维持原有的单音效行为。
- 发送：`POST /api/chat/stamps` 复用一次 Auth 身份校验，根据已缓存的私有 Master 验证 region/id/kind。一次 `authorize_chat_stamp` RPC 读取已有资料、锁定账号状态、检查禁言并消耗独立的每 60 秒 20 次固定窗口额度。只在 `chat_private.user_state` 增加两列，不新增表、消息记录或 outbox；同一 RPC 返回广播所需名字和 UID，没有额外资料/邮箱验证查询。
- 鉴权通过后，共享发布进程在滚动一秒内最多广播五个 stamp，超出静默丢弃，仍消耗个人额度，HTTP 响应不披露房间限流。无排队、重试、重放。此内存闸门要求一个 Next.js 发布进程；以后增加应用副本或 worker 前必须迁至共享发布入口。
- 广播只有事件类型/UUID、用户 UUID/公开 UID/名字、stamp 的区域/ID/类型。接收端复用评论区目录缓存解析媒体，不逐条查询资料、权限或历史。发送者立即播放并忽略自身回显；临时失败不添加提示或失败 stamp 历史行。重连只重新读取已保存的文字/图片。
- 通用标识/名字底板使用 `bandori/resources/atlases/menu-atlas/{icon_voice_stamp,label_round_white}.png`；通用音效使用 `bandori/resources/audio/common/SE_UI_STUMP.wav`，通过既有 CDN helper 生成 URL。PNG 来自 JP APK，音效来自 JP `sound/common` → `LiveMenu.acb`，不把它误记为 APK 资源。Builder 本地保存来源/hash 报告，相同字节跳过，不覆盖既有不同内容。无公开 manifest 或定时同步。
- 发布顺序：先发布两个新增固定资源（标识复用现有对象），再应用 `20261024124049_chat_stamps.sql`，最后部署匹配的应用并使用现有聊天开关。本轮授权固定素材发布和本地实现/测试，不包含网站或远端数据库部署。
