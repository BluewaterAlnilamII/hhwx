# OurNotes 歌曲图鉴

[English](ournotes-songs.md)

`/ournotes/songs` 和 `/ournotes/songs/{songId}` 沿用 Bandori 歌曲图鉴。两款游戏共用歌曲列表行、筛选工具栏与等级／排序控件、详情页头、标签、统计栏和难度按钮；各自的数据适配保留游戏字段、区域和搜索含义。共享展示组件不加载模拟器。

## 图鉴视图与布局

图鉴顶部有两个等宽标签：**歌曲／谱面 Meta**（英文为 **Songs / Chart Meta**）。`/ournotes/songs` 打开歌曲列表，`?view=meta` 打开谱面 Meta，切换时保留其他查询参数。歌曲详情的信息／模拟器标签是独立控件，保留原有名称和行为。

图鉴标签、筛选和 Meta 参数遵循[主题指南的紧凑布局](theme-guide.zh-CN.md#图鉴筛选与-meta-参数布局)。标签栏紧接筛选面板，Meta 筛选紧接独立参数区，参数区没有可见子标题。连接处均为零间距、单条 1px 分隔线，选中标签指示线保持 2px；结果区保留独立间距。参数区仍有“参数设置／Parameters”可访问名称，间隔字段显示“演出间隔／Live interval”，不重命名 URL 或存储中的 `downtime`。

## 数据与区域

列表通过 `useOurNotesMaster` 并行读取现有 Music、Bands master API。详情与 metadata 使用私有 Music detail reader，并在同次请求内去重；只将分区展示需要的字段传给详情客户端。浏览器通过按 URL 缓存的公开音乐索引解析官方 `thumb` 和 `jacket`。图片描述符必须符合 OurNotes 的内容寻址 PNG 路径；缺图保持不可用，服务端不回退到公开 CDN 读取元数据。

五槽为 JP／EN／TW／CN_INTL／KR，CN_INTL 在界面显示为 CN。展示服使用已有 OurNotes 工具栏偏好，默认 CN，与网页语言、Bandori 偏好独立。首选槽不可用时按 JP／EN／TW／CN_INTL／KR 回退。分类、难度、属性和任务先应用所选地区的完整覆盖及删除。歌曲标题优先使用 JP 槽作为原版曲名，JP 为空时回退到最终展示服的曲名；列表显示及名称排序、详情页头、metadata 和加入播放器的曲目统一使用该规则，搜索仍包含全部区域曲名。其余区域文本和数字缺失时保持缺失，不从另一服补齐。通用乐队筛选名称允许沿用已有文本回退。

可用服务器筛选只控制收录，不改变展示偏好。歌曲存在由 `serverExtensions` 判断，不由 `startAt` 判断，也不代表当前可玩或已解锁。列表行展示已知最早的正值开放时间；区域日期排序各用本服 `startAt`，按 Music 合同使用 JST 格式化。缺日期在两个排序方向均放最后；历史及未来记录继续保留。

## 列表行为

- 默认歌曲 ID 倒序，与 Bandori 一致；另外提供名称、等级和五个区域的开放日期排序。API 的 `sortOrder` 继续表示游戏原生顺序，不替代图鉴默认值。
- 筛选使用 `q`、`available`、`bands`、`types`、`difficulty`、`minLevel`、`maxLevel`、`sort`、`direction`。未提供选择参数表示全选，显式空值表示不选。`available=cn` 与 `available=cn_intl` 指向相同槽位。列表及详情移除旧 `server` 参数，保留偏好及 URL hash。
- 组内取 OR，组间及搜索条件取 AND。多乐队歌曲匹配其中任一乐队；没有已知目录乐队的歌曲归入“其他”，包括 CRYCHIC 等歌曲专用演唱单位。
- 分类为原创、虚拟歌手、J-POP、动画、游戏、Another Band。`musicType` 是独立的歌曲属性，不作为分类。未知或无分类歌曲保留在未限制分类的图鉴中；不匹配显式选中的已知分类。
- 搜索复用图鉴的 NFKC／大小写归一化、已审核 OurNotes 乐队别名、服务器别名及难度比较。完整乐队名作为短语；未知词搜索各区域的歌曲名和演唱单位名。`/名称`、`"名称"`、`“名称”` 只搜索歌曲标题。已识别身份不回退到无关标题文字。
- 裸正整数匹配歌曲 ID 或显示等级，`#ID` 仅匹配 ID。难度及等级支持 `+`、`-`、`>=`、`<=`、`>`、`<`；全部难度／等级条件须由同一张选中谱面满足。Anime 对应 OurNotes 动画分类，不沿用 Bandori 的翻唱含义。
- Enter 或搜索按钮提交，删空立即清除已提交查询，并保留输入法保护。等级在 Enter 或失焦时提交；清空同时删除已提交条件和未提交等级草稿。首批 40 条，每次再显示 40 条；查询变化重置批次，浏览器历史保留列表 URL。
- 首次加载等待必要数据及偏好恢复。依赖首次失败显示重试，不显示误导性的空结果；刷新失败保留有效数据，只重试失败依赖。

## 谱面 Meta

### 参数与计算

Meta 通过 `useOurNotesMaster` 并行读取 Music、Bands、Skills 和 `music/meta`，等待必要数据及浏览器偏好恢复后再显示控件和结果。计算遵循 [Meta API 与计算契约](ournotes-master-api.zh-CN.md#谱面-meta)，不下载谱面／音频，也不重复应用音符类型出分系数。自由演出可用，激奏演出入口保留且禁用，没有 Fever 控件。

| 参数 | URL／偏好字段 | 首次使用默认值及有效范围 |
| --- | --- | --- |
| 演出模式 | `mode` | 仅 `free` |
| 成员技能与等级 | `liveSkill`、`liveLevel` | `5`（PERFECT 以上得分提升 150%），5 级；等级 1–5 |
| 留影技能与等级 | `supportSkill`、`supportLevel` | `11`（MyGO!!!!! 条件下延长 5 秒），5 级；等级 1–5，技能可选 `none` |
| Perfect 率 | `perfect` | 100%；0–100 的有限数，允许小数 |
| 演出间隔 | `downtime` | 30 秒；0–3600 的有限数，允许小数 |
| 表格排序 | `metaSort`、`metaDirection` | `score`、`desc`；独立于歌曲标签的 `sort`／`direction` |

技能选项使用偏好服的完整效果，仅在该服缺少技能时回退首个可用服。五个等级均须支持；效果、说明和说明参数完全相同的重复选项合并。成员选项包含已支持的得分提升，留影选项包含装配成员的演出技能延时；分数等级触发加分、纯判定和纯生命技能不加入。条件取满足分支，不叠加互补分支；页面不增加条件说明注脚。组合时长未发布时显示既有的组合不支持状态。

### 结果与说明

每行对应一个歌曲／难度组合。列顺序为 **排名、歌曲、难度、分数、效率、时长、BPM、N、NPS、SR**。首次按未舍入分数降序；首次点击其他数值列使用降序，歌曲列使用升序，再次点击当前排序列切换方向。缺失的排序指标在两个方向均置后。歌曲标签仍默认按歌曲 ID 倒序。

时长使用 `分:秒.毫秒`，四舍五入至毫秒。分数、效率、NPS 和 SR 固定两位小数，保留末尾零；BPM 四舍五入为整数，N 保持整数。BPM 取最长单个速度区段，多种不同 BPM 加 `*` 并提供各值。官方 `fullComboCount` 作为音符数 N，`N / length` 作为 NPS。SR 包含技能重叠累计，可以超过 100%。缺失或无法计算的 Meta 谱面不参与排行，缺失展示指标保持不可用；曲名继续优先 JP，缺失时回退当前服。

歌曲列左对齐，其他表头与数值居中。表头文字与说明图标作为整体居中，排序箭头独立定位，不因切换排序撑大列宽。从分数起、除时长外，使用既有 `HelpPopover`，文案如下：

| 栏目 | 中文 | 英文 |
| --- | --- | --- |
| 分数 | 出分相对于综合力的比率 | Score relative to total power |
| 效率 | 每分钟平均出分相对于综合力的比率 | Average score per minute relative to total power |
| BPM | 每分钟节拍数 | Beats per minute |
| N | 谱面音符总数 | Total notes in the chart |
| NPS | 每秒平均音符数 | Average notes per second |
| SR | 技能覆盖率 | Skill coverage |

小于 `sm` 时，表格仅在自己的面板内横向滚动，最小宽度 768px；歌曲列最小 120px，曲名最多显示两行。`sm` 起表格最小宽度 960px，歌曲列最小 164px，曲名不截断行数。数值列保持紧凑，剩余宽度分配给歌曲列，不允许表格撑宽整个页面。

分数与效率分别加粗当前技能、Perfect 率设置下，已解析目录中所有可计算歌曲／难度组合的前 5% 数值；效率同时使用当前演出间隔。各自取按未舍入数值倒序排列的第 `ceil(谱面数 * 0.05)` 项作为门槛，门槛处完全相等的并列值全部包含。搜索、服务器可用性、乐队、类型、难度、等级和排序操作不改变比较范围；无法计算的谱面不计入总数。

### 浏览器偏好

`hhwx:ournotes:song-meta-preferences:v1` 保存参数表中的九个字段。偏好属于当前浏览器，在不同界面语言间共用，与首选服务器和 Bandori 设置独立。显式 `supportSkill=none` 及其留影等级均保留。普通图鉴筛选仍属于 URL 状态，不加入这份偏好记录。

有效的显式 URL 参数优先于已保存偏好，再回退默认值；技能可用性在 Skills 加载后解析。完整生效设置写入 URL 以便链接复现，但不将链接中的设置自动保存为偏好。只有用户主动修改才更新对应字段。数字输入在 Enter 或失焦时提交有效且有变化的值，无效草稿恢复为当前值。打开链接、恢复状态或不可用技能回退均不覆盖原选择；本地存储损坏或被禁用不阻断页面操作。“清空”仅移除图鉴筛选，保留当前参数和表格排序，同时清除未提交的等级筛选草稿。

## 详情行为

详情沿用 Bandori 方形封面／页头、等宽信息／模拟器标签和四格统计栏，窄屏为两列。谱面模拟标签始终可见且禁用，键盘同样不可进入；`view=simulator` 规范化回歌曲信息。该页面不请求模拟器运行时或谱面；仅在全局播放器需要所选歌曲时加载音频。

OurNotes 仅有 EASY／NORMAL／HARD／EXPERT。模拟器禁用期间，难度按钮放在歌曲信息区。默认选择展示服引用的最高难度，`difficulty` 保存显式选择；切换展示服后若原难度不存在，改选该服最高引用难度并规范化查询。非法 ID、不存在歌曲、非法难度名称、所有区域均未引用的难度返回 not-found；源读取失败使用路由错误与重试界面。

等级标签按已核实的原生行为，将 `musicScoreDisplayLevel` 向零截断；等级排序保留小数，搜索和等级范围比较显示整数。因此 `20.5` 显示为 `20`，排序高于 `20`，不转换成 `20+`。`musicScoreLevel` 仍是 API 独立保留的原生值。

数量栏显示官方 `fullComboCount`，文案为连击数；同一个官方计数也作为 Meta 的音符数 N，不另行统计原始谱面对象数量。BPM 使用所选难度已发布 BPM 值的最小／最大值；时长读取 API `length`，按分秒显示。统计不依赖谱面或音频下载。缺少 score 行、字段或媒体不填零，也不使有效歌曲详情消失；已知 BPM 可以与缺失的官方 score 数据并存。

属性与三个激奏任务位使用共享详情信息行。任务保留槽位顺序、重复值、显式 None、未知代码和缺失值；列表不新增属性／激奏筛选。奖励、获取途径、MV、额外演唱、玩家解锁不属于本次图鉴范围。Metadata 沿用歌曲页按网页语言选择区域的方式，无法读取浏览器偏好。

## 图鉴播放

两侧列表和详情头部共用难度条，末尾紧接活动页样式的 28 × 28 px 播放按钮。桌面保留难度名称；小于 `sm` 断点时只显示数字，维持固定难度颜色与顺序，同时保留读屏名称和完整提示。详情头部使用移动端 80 px、桌面 128 px 封面，难度条放在演唱单位下方；原有难度选择器继续承担选择职责。

图鉴播放保留临时队列：新歌追加，已存在歌曲按带游戏前缀的 ID 定位；点击当前歌曲切换暂停／继续。达到既有持久化上限 500 首时停止追加，不移除已有歌曲。Bandori 活动页保留原有替换队列行为。新增 `ournotes` 来源沿用 v1 快照格式，兼容读取既有 Bandori／Falcom 队列；刷新恢复后保持暂停。

OurNotes MP3 描述符须匹配 `ournotes/music/audio/{sha256}.mp3`，摘要有效、大小为正；可选索引时长须为正有限值。播放器复用图片所用的索引缓存，不猜测媒体路径。缺少音频时禁用按钮，单独浏览图鉴不下载歌曲音频。谱面模拟标签继续禁用。

## 验证

`npm run test:ournotes-songs` 覆盖区域、缺项、原生等级显示／排序、搜索组合、分类、URL 往返、任务、图片／音频描述符，以及 Meta 完整性、技能支持、计分、前 5% 排名和偏好。按 [CONTRIBUTING](../CONTRIBUTING.zh-CN.md) 根据受影响调用者选择其他套件：共享音乐／模拟器变动使用 `test:bandori-music`／`test:bandori-chart-simulator`，卡牌行为使用 `test:ournotes-cards`，master reader 变动使用 `test:ournotes-master`。按相关性执行 typecheck、lint、i18n 和 build；单纯 CSS 或文档修改不要求运行全部套件。

浏览器验收使用 `http://localhost:3000`，在桌面／手机、中英文和明暗主题下对照 Bandori 与 OurNotes；检查搜索、清空、排序、分页、历史、偏好切换、难度选择、禁用标签及失败重试，并确认 OurNotes 未请求模拟器媒体。构建与单元测试本身不证明视觉一致或生产部署。

Meta 还需检查刷新与语言切换、显式 URL 优先但不覆盖保存值、不可用技能、无效／禁用存储、数字 Enter／失焦提交、连续失焦再点击、排序切换和清空保留参数。验证说明浮层的触控／键盘行为、排序不改变列位置、分数与效率独立加粗、窄屏换行，以及表格只在面板内滚动。
