# 全新 Bandori 组曲搜索

英文版：[bandori-medley-search.md](bandori-medley-search.md)

## 依据与目标

本文记录已经批准、仍可复核的搜索设计，不新增游戏规则。输入与计分以[基础说明](bandori-medley-foundation.zh-CN.md)为准。代码独立于旧组队器及实验实现；Calc 只用于借鉴提前剪枝与短期紧凑存储，不定义 HHWX 计分和最优证明。

对每套三队共用的合法已拥有道具，选择三支五卡队伍。每队角色不同，三队不复用物理卡，排除标记是硬限制。歌曲保持输入位置，允许重复。正式目标是三曲平均分总和的、已证明的 Top-1；同分保留稳定代表。最多十个已发现方案只供诊断，不是证明过的全局 Top-10。

## 完整队伍精确计分

实例 ID 按 HHWX 档案顺序产生。五卡集合按实例 ID 排序，把选中队长移到成员索引 2，其余成员相对顺序不变。同曲同分保留先遇到的队长。道具顺序与最终 `(歌曲0 + 歌曲1) + 歌曲2` 的相加顺序不变。

计分遵守 `hhwx-medley-bestdori-v3`：从 BPM 点换算时间，基础运算顺序及平均判定／技能倍率沿用 Bestdori，窗口增分分别取整后相加，每曲最终均值再向下取整。前五次 120 种顺序仍等概率，第六次重复队长。没有 P/G 历史状态，也没有重叠联合计分路径。

- 每次输入只准备一次 combo 分段和触发音符索引，不改变现有音符排序。
- 每个五卡集合只解析一次全队技能条件。每曲只查一次各技能的六个终点；恒定倍率只算一次，增长技能只在覆盖第 100 个音符之前变化，持续 PERFECT 技能可能整窗变化。变化部分的倍率由六窗及所有队长共用。
- 每个 combo 段只取整一次基础分。恒定技能在每个相交 combo 段算一次整数增分，再乘音符数；只有倍率确实变化的部分仍逐音符取整。
- 汇总 30 个成员／窗口的整数增分，重叠也同样处理。队长 `l` 的均值分子是 `5*(基础总分 + 增分[5][l]) + 前五窗全部增分之和`，只转一次浮点数，除以五后向下取整。候选比较与组曲总分都使用各曲已经取整的分数，不生成 120 个顺序分数。
- 仅综合力浮点位值完全相同的队长候选共用基础分；不能抹掉成员重排带来的综合力加法末位差异。

有符号 i128 足以精确容纳 u32 音符数与音符分下的全部累加，也保留负增分，因此无需第二套逐音符浮点累加的回退路径。独立参考实现仍枚举 120 种顺序，把总和的公因子 24 约去后，按同样方式转换、除以五并向下取整，与生产结果逐位对照。

## 部分队伍分数上界

先准备谱面／combo 系数及技能时长覆盖，每套道具配置再给出各卡综合力上界。部分搜索节点不重新扫描谱面。

对仍可能达成的全队技能条件，理想平均分不超过 `P × K`。`P` 是五卡综合力上界之和；`K` 包括基础系数、前五次贡献和恰好一名队长的第六次贡献。基础分使用输入 PERFECT 率对应的平均判定系数，技能取当前平均倍率公式的非负上界；去掉负贡献只会抬高结果。每张卡在前五个位置各出现 24/120 次，所以系数是五个窗口贡献之和除以五。

对任何正权重 `t`：

```text
P × K ≤ (t × P + K / t)² / 4
```

用小规模动态规划求右侧括号的最大值：每个剩余角色至多一张卡、恰有一名队长、已选卡不变，综合力与技能贡献仍绑定在同一张卡上。对可达同团／同属性条件取最大值，同一条件内对合法权重取最小上界。这是上界，不代表所有有利选择能同时实现。五卡全部确定后，按实际全队技能条件直接向上计算 `P × K`，不再做加权最大化；音符分范围检查和最终均值舍入证明不变。

只为当前道具配置准备每曲的三组权重，以及各角色、技能条件下完整排序的普通成员／队长卡牌列表。一张卡最多属于四种条件；移除时只推进受影响列表的可用首项，回退时按改动记录恢复。上界与临时组队建议共用这份可用状态，参数范围检查也有自己的排序列表。列表不截断，每轮上界不再扫描全部剩余卡。上界顺便选出的五卡仅用来安排搜索顺序，不是已经算出的最优队伍。

浮点证明包含：

- 从正式计算已舍入的卡牌／活动小计和道具乘积出发，向上覆盖各种队长顺序中剩余的综合力加法。
- 技能倍率上限遵守正式公式的运算顺序。增长技能取封顶端点；持续技能只准备一次实际 `powf` 在谱面音符数范围内的最小／最大值，不猜库函数误差。
- 把按 Bestdori 顺序算出的基础系数作为确定值，向上覆盖之后三次乘法。基础中间值小到进入非正规数范围时，不足以产生一个整数音符分。
- 技能倍率上界大于一时，向上取相邻浮点数以覆盖音符分乘法舍入，减一后再向上一步覆盖减法舍入；由此覆盖每个独立整数增分。
- 独立检查整个部分队伍的参数上界，证明基础音符分和单个技能作用后的音符分不越过 u32；不能只检查加权求出的那支队伍。
- 总分用有符号整数精确累加。如果 `C` 是理想均值的上界，由转换和除法的单调性，`f64(5*C) / 5` 就覆盖实际均值。每曲最终向下取整只会降低分数，因此原上界仍然安全；不再需要原来的 120 次加法误差范围。

证明不可用时上界为正无穷，不能判无解。只有整套三曲上界严格低于精确算出的当前最高分才能剪枝，同分仍需搜索。

## 三队联合分配与批量剪枝

对较大的搜索范围，把三队不能复用物理卡直接纳入上界。仍复用原有综合力／技能系数；尚未确定的全队条件，逐卡保守取最大值，不展开三队条件的全部组合。把已选卡综合力 `P0`、基础与已选卡前五次技能系数 `K0`，和剩余综合力 `Pr`、剩余技能贡献 `Kr` 分开；尚未选定的队长贡献计入 `Kr`：

```text
P×K = P0×K0 + P0×Kr + K0×Pr + Pr×Kr
Pr×Kr ≤ A²/4 ≤ M×A/4，A = t×Pr + Kr/t，0 ≤ A ≤ M
```

只有剩余乘积需要放宽，其他部分直接作为常数或线性项。小型单队计算给出 `M`，沿用三种正权重，但按包含全部项的最终上界选较小者，不能只比 `M`。所有系数非负并向上舍入；剩余综合力或技能贡献为零时只需线性项。完整队伍已经算出的对应曲分数直接计入常数；尚未精算时，其直接 `P×K` 上界也足够。

联合计算按角色处理，每个角色有 27 种“不选／普通／队长”的分配方式。未选人的队伍用十种数量状态；部分已选、还差 `r` 人的队伍用 `2×(r+1)` 种；完整队伍只用一种。因此 1,000 是最大状态数，不是每轮固定开支。已选卡退出剩余分配，同队也不能再选其角色；已选成员中最强的队长贡献可作为初始选项，不占剩余名额。角色内部禁止同卡复用，并保留所有必选卡。每种身份的前四张足以处理局部匹配：另两种身份和一张禁用卡最多挡住三个更优替代；必选／指定卡单独补入。完整卡池中的每张卡仍检查所有允许去向，不截断搜索卡池。

前后计算表把角色内的分配与外部剩余名额相连，一轮便能给出每张卡去三队或不用的上界，不为每个去向重跑整套计算。向上相加和四步运算误差范围覆盖正式均值转换与三曲相加。只有上界严格落后或分配确实不存在，才删除去向；只剩一个去向就直接确定。同批裁剪都基于包含当前范围的同一父范围，允许一起应用。上界选出的完整分配交给原计分器计分，不冒充最优解。

权重、角色内选择、前后表和各卡去向上界一起保留。新增已选成员或完整队伍的实际分数后，重建更小的计算；否则，原最大权重分配仍合法时直接复用上界。分配被排除时，复制父节点工作表，只重建受影响角色的选择，向前后传播到数值不再变化的位置；只有角色去向或外部行变化，才重算对应去向上界。祖先表对后代始终安全，只是可能偏松，最后一个使用者退出时释放。这是有预算的复用，不是候选截断；一次更新仍可能传播到所有角色。

## 早期找分与完整搜索

1. 找到合法十五卡分配。启发式找不到，不代表无解。
2. 按完整队伍估算给道具配置排序，但准备时已经构造出的完整方案立即精确计分。最多先探测八套配置，各尝试至多六种确定性的分卡顺序和权重，正式遍历沿用每 512 个节点逢未剪枝时补全一次的时机。一次探测内去重三队组合，每个新组合只检查一轮：最多 75 种跨队单卡交换，以及从三队上界建议的并集中取卡的 225 种单卡替换；只重算受影响队伍，合法性与缓存省略之前最多 375 次五卡计分。用已有三曲分数检查六种队伍分配，歌曲位置不动。涨分不触发下一轮换卡，启发式失败也不删除搜索范围。
3. 每次处理一套配置，用显式深度优先栈、可撤销的可用状态，以及每张卡四个位表示允许去向。必选卡不推进普通角色顺序；计数和枚举遵守本队允许去向、已跳过角色及已选角色。另一队仍能使用同角色的另一张卡。
4. 新计算前先检查继承的联合上界和单队上界，新旧有效上界取较小者。五卡固定后先过廉价上界，再精确计分并沿路径保留。单队排序首项可以暂时忽略仅对某队的排除，得到偏松但安全的上界；联合分配和实际枚举始终遵守已排除的去向。
5. 三队合计能装进 256 行局部候选或剩余预算允许的更小范围时，完整枚举组合。否则联合批量剪枝，再选择一张未确定卡分支，保留所有允许去向（包括不用）。条件上界差距和最大权重分配只影响先搜哪里。新一轮联合计算装不进预算或证明不可用时，有祖先条件表就继续用其安全但偏松的上界；完全没有表才走完整的单队上界／归属／角色顺序遍历。两种情况都遵守已删除的去向，不能因优化不可用而丢掉未排除的分支。
6. 局部候选按对应歌曲分数排序，拒绝物理卡冲突，并确保“不用”已被排除的卡确实入队，再按总分停止扫描。第三队略低也可能因浮点相加而总分相同，因此仍保留最终总分相同的所有行，选出稳定代表。
7. 每块结束释放候选和排序索引；固定容量、仅当前配置有效的缓存复用五卡结果。缓存冲突或驱逐只会重新计算。

256 行切块、缓存容量和启发式次数是工作量控制，不是候选截断。组合计数只在 u64 上限饱和以便安排顺序，小块阈值以内仍准确。显式栈容纳连续“不用此卡”的长路径，不递归到同样深度；普通遍历节点共用上界记录，不复制卡池。不保存全局候选池、候选对表、每行卡池位图或全局待搜索队列。最坏情况仍是指数规模。

## 完成状态与资源统计

全部配置和范围穷尽或安全剪枝后才返回 exact。取消、超时、内存不足、数据错误、算术溢出、计分不一致、计数／索引溢出及内部错误都返回 incomplete，可附诊断用 `bestSoFar`。高分不等于完成证明。

存储预算包含局部候选／索引、计分缓存、联合计算预留量，以及全部仍存活的祖先记录，包括权重、卡牌去向、角色内选择、状态转移、前后表、回溯选择和去向上界。`peakSearchStorageBytes` 包含新建／复制的保守预留，不是实际堆内存采样；`peakCandidateBytes`、`peakCacheBytes` 仍只统计各自部分。40 个角色、1,000 个状态的一份前后表及回溯选择约需 0.665 MiB，已选成员会缩小它。不能只为压低 RSS 而放弃有用复用。输入／模型／配置、单队上界索引及撤销、计分临时数据和遍历数据仍在此预算之外。原生诊断单列其容量并采样进程内存；不同峰值不能相加冒充同时占用，也不是浏览器／WASM 增量内存。

停止检查位于节点／候选及逐角色表计算之间，不在模型准备或单次完整计分内部，截止时间不是硬实时保证。原生诊断记录联合上界耗时、删除去向、确定卡、直接复用上界、新建模型、更新工作表、状态数、重算行数和预留字节；这些不能代替实际涨分和证明进展。完整队伍计分次数是缓存未命中次数；`exactSongScores` 每组五卡记 15 个歌曲／队长结果，不代表扫描了 15 次谱面。

## 验证与停线

计分纠错使用小型上游公式对照、与参考逐位比较（含重叠及不同队长参数）、已有极小穷举的不同预算／配置、上界覆盖、同分和未完成状态，并做必要类型／编译检查。仅修改计分时，不例行复算历史队伍，也不自动重跑长时间真实档案基准。

真实谱面的单队计分检查用 `node --import tsx scripts/benchmark-bandori-medley-score.mjs --main <干净的main工作目录>`。它使用保留的 119／961 卡资料和六张真实 expert 谱面，测试 100%／95% PERFECT、combo 从零开始／跨曲延续，并包含两支使用真实卡牌的技能变体队伍。先与 Bestdori 原始转换函数核对音符时间和触发顺序，再计分。计时比较同一综合力下含选队长的计分，关闭 main 的已算分数缓存；精度使用固定版本的 Bestdori 原始函数，并按 HHWX 要求对每曲均值向下取整。上游单窗口／普通 combo 与 HHWX 的明确规则差异分开报告。输入、代码哈希、耗时和结果留在忽略目录 `temp/medley-score-benchmark/`；这只是原生 Rust 与 Node 的对照，不代表浏览器／WASM 或完整搜索吞吐。

获批完整搜索基准仍另行保留，保持相同输入和预算，历史结果不能作为搜索种子。私有证据按[档案说明](bandori-medley-fixtures.zh-CN.md)留存。

诊断当前搜索用 `node --import tsx scripts/compare-bandori-medley-search.mjs --diagnose`，追加 `--case 119-no-event` 可只运行该例，也可指定 `--case 1229-event-244` 这样的已留存场景。`--duration-ms`、`--local-row-target` 和 `--score-cache-slots` 只用于有时限的 A/B 测量，不改变正式搜索参数。默认诊断从原始档案和主数据重新生成当前规则下的 119／961 卡无活动输入，每例运行 60 秒，沿用 256 MiB 存储预算和 1 GiB 采样进程限制。结果直接列出与归档历史平均分的差值，保留原设置和已知缺项；历史成绩不传入搜索，不运行旧算法或复算旧队伍。仅原生诊断测试包含计时，记录互不重复的阶段墙钟耗时、上界计算轮数／排序首项访问次数、有界换卡工作和严格涨分时间点；嵌套调用只计一次。首项访问次数不能和以前整池扫描的卡牌访问次数直接混算。耗时包含计时本身的开支，不是未插桩吞吐基准。输入哈希、提交、结果、计数和原生进程内存保存在私有 `runs/` 目录。到达诊断时限只代表测量完成，不代表已经证明最优；`passed` 仍要求完整证明且分数不低于历史参考。

本轮搜索范围不包括支配关系、分数量化、SIMD/FMA、近似保留、外部存储、新依赖、前端／API 接入或理论最高分输出。
